# 기존 수집 자료의 활용 분류

접속: https://moa.h19h19.com/corpus (기존 검수 암호로 로그인).
원문·다운로드·분류 변경은 모두 기존 세션/CSRF 보호를 사용한다.

## 분류와 승인 구분

| 분류 | 의미 | 추천·활용 조건 |
| --- | --- | --- |
| 활용 후보 · 미승인 | 현재 파서로 읽힌 안내 파일 | 원문/변환 대조 및 사람 승인 전에는 추천 사례 아님 |
| 원본 첨부 전용 | 별도 신청서·동의서·참고자료 | 원본으로 보관/다운로드, 안내 구조 학습에서 제외 |
| 보류 · 확인 필요 | 경계·누락·이전 파서·미분석·개인정보·내용 부족 | 문제 확인 후 재분류/콘텐츠 재검수 |
| 활용 제외 | 사용자가 권리·무관함 등 사유로 제외 | 검색·추천·활용 내보내기 제외, 원본/승인 이력 보존 |
| 평가 전용 | 기존 eval 사례 또는 사용자가 평가 전용 지정 | 추천·학습 입력에서 제외, 다시 후보로 변경 불가 |

문서 집계와 파일 집계는 다르다. 안내 후보에 신청서가 붙어 있으면 문서는 후보,
신청서는 첨부 전용이다. 안내 파일에 보류 사유가 하나라도 있거나 원본 파일이
없으면 문서는 보류한다. 원본 첨부 전용 파일은 미지원 파서여도 실제 파일을 보관할 수 있다.

자동 분류는 한국어 파일명/제목, 서식 필드, 기존 추출 상태를 이용한 **보수적 로컬 규칙**이다.
모델 훈련·외부 AI 호출·새 수집·원본 삭제를 하지 않는다. 정확한 자동 정답을 보장하지 않으며
불명확한 안내/서식 경계, 이미지와 스캔, 이전 파서 결과는 보류한다.
`train/dev/eval` 분할과 별개로 파일의 활용 가능성을 확인한다. 한 문서에 eval 사례가 있으면
안내 전체를 평가 전용으로 분리한다. 모델 가중치가 재학습되었다고 표시하지 않는다.

## 웹 사용 순서

1. 상단 **기존자료 분류**에서 분류 필터를 선택하고 통신문 제목을 연다.
2. 실제 원문 페이지·원본 보기/다운로드, 파서 상태와 보류 사유를 확인한다.
3. 파일 역할(안내 모바일 변환/원본 첨부 유지), 활용 분류와 선택 메모를 저장한다.
   확인자 이름은 입력하지 않고 접속별 검수 번호·시각을 자동 기록한다.
   개인정보 탐지 자료를 후보로 바꾸려면 원문 대조 체크와 확인 결과 메모가 필요하다.
   미분석·이전 파서·원문 누락은 확인 체크만으로 후보로 승격할 수 없다.
4. **모바일 변환·원문 비교·콘텐츠 검수**로 이동해 현재 파서로 생성하고 원문과 대조한다.
   혼합 문서는 안내/서식 시작 경계를 먼저 확인한다.
5. 콘텐츠 승인·보류·수정·반려·승인취소는 기존 변환 버전 검수 화면에서 별도로 수행한다.
   분류 저장은 승인하지 않는다. Codex는 운영 실자료를 대신 승인하지 않는다.

같은 화면에서 두 번 저장하거나 다른 사람이 먼저 변경한 경우 최신 분류 fingerprint로
다시 확인한다. 파일 역할 변경은 과거 HTML을 덮어쓰지 않고 새 후보 변환을 대기열에 넣는다.
제외/평가/보류로 바꾸면 과거 승인 기록은 보존하되 승인 규칙 검색/내보내기에서 제외한다.
파서·원문·경계가 변경되면 이전 수동 분류를 변경 이력으로 남기고 다시 후보를 만든다.
같은 물리 파일을 평가용 업로드 또는 다른 게시글에서 지정해도 추천에 재유입되지 않도록 검사한다.
미분류인 기존 승인 기록은 보존하되 분류를 마칠 때까지 활용에서 제외한다.

기존 사람이 승인한 짧은 표는 전체 안내문으로 분류되지 않더라도 표 구조 사례로 보존한다.
이 예외로 누락/개인정보/미분석/이전 파서/평가/사용자 보류를 우회하지 않는다.
`learning/candidates.jsonl`은 검수용 후보이며 `unreviewed_not_training_input` 표시를 유지한다.
제외·서식·평가 자료는 활용 후보 내보내기에 섞지 않는다. 승인된 내용만 추천에 사용한다.

## 운영 명령

`/volume2/moa/app`에서 실행한다. 기존 일일 400건 목표/04:00 스케줄/백필을 변경하지 않는다.
분류는 수집 잠금이나 HTTP 요청 예산을 사용하지 않고 DB의 분류 작업을 원자적으로 가져온다.

```sh
sudo docker compose exec review python -m moa corpus status
sudo docker compose exec review python -m moa corpus queue
sudo docker compose exec review python -m moa corpus classify --batch 50
```

`--batch`는 1~500. 재실행/재부팅 시 미완료 대기열에서 이어서 처리하며 자동 승인은 없다.
웹 서비스가 살아 있으면 분류 대기열도 계속 처리된다. 개별 자료는 웹의
**현재 원문·파서 상태로 분류 갱신**으로 다시 확인한다.
스키마 v4는 기존 notices/cases/승인/원문을 초기화하지 않고 분류·이력 테이블을 추가한다.
DB 변경 전 SQLite 온라인 백업을 생성한다. GitHub에는 코드·합성 테스트·사용법만 보관한다.
