# MOA — 동일 이진 후보의 추가 재개 1회

## 범위

사용자의 최신 허가는 **기존 후보를 추가로 한 번 재개**하는 것이다. 새 후보,
추가 훈련시간, 학습 설정 변경, 다른 앱 종료 허가가 아니다.

고정 작업은 `moa-unattended-20261021-binary-train-01`이다.
기존 비교와 같은 격리 맥미니 CPU·R1 초기 가중치·합성 train 108/dev 54·두 선택지·
seed·4 epochs·encoder 동결·학습률 계획을 유지한다. 맥북이나 NAS에 새 작업을 발행하지 않는다.

## 중단 원인과 메모리 보호

앞선 첫 실행과 자동 재개는 모두 모델 적재 후 가용 메모리가 5GiB 아래로 내려가
첫 업데이트 전에 안전 중단됐다. 누적 5.91초, 0 updates이며 새 성능 측정 결과가 아니다.

이번 확인에서 종료할 수 있는 MOA 잔여 학습 프로세스는 없었다.
다른 활성 앱·사용자 작업·서비스·OS 전역 캐시를 종료하거나 비우지 않는다.
모델 적재 전 5GiB만 확인하면 적재 후 다시 하한을 밑돌 수 있으므로,
이번 한 번의 재개는 **적재 전 최소 7GiB**를 요구한다. 적재 후 기존 **5GiB**
안전선과 AC·15분 사용자 유휴·메모리 압력 검사는 그대로 유지한다.
메모리를 충분히 확보하지 못하면 허가를 소진하지 않고 대기한다.

## 정확히 한 번 재개하는 방법

- 기존 PLAN/STATE/후보 허가 및 실패 영수증을 비공개 외장 SSD에 보존한다.
- 학습 코드·입력·모델·예산은 고정하고, 수정한 컨트롤러 소스 pin만 명시적으로 갱신한다.
  기존 후보 허가의 PLAN 해시 연결도 갱신하되 추가 후보를 주지 않는다.
- `RESOURCE_RESUME_AUTHORIZATION.json`은 변경 전 상태·실패 결과·저장 경계·
  원래 예약 날짜에 연결한다. 과거 재개 경계 목록은 삭제하지 않는다.
- `RESOURCE_RESUME_DISPATCH.json`을 한 번만 저장한 뒤 동일 worker를 `--resume`으로 실행한다.
  발행 직전부터 허가를 소진한 것으로 기록한다. 부분적인 상태 복구로 재사용할 수 없다.
- 재개 후 다시 자원 보호로 중단되거나 원인 불명 종료가 발생하면 추가 훈련을 발행하지 않는다.
  새 저장 경계가 생겨도 이번 허가로 두 번 재개하지 않는다.
- 성공하면 기존 별도 프로세스 평가와 동일 두 선택지 순서 비교를 이어간다.

후보의 기존 1800초 예약은 반환·초기화·추가하지 않는다.
원래 예약일(한국시간 2026-10-21)을 넘겨 재개하지 않는다.
예정 56 updates, 최대 120 updates/누적 1800초, 별도 평가 누적 600초를 유지한다.
현재 이 후보까지 포함한 7일 예약은 10575.63초, 당일 예약은 3600초다.
이는 실제 완료 훈련시간이 아니라 안전 예산 원장의 예약값이다.

## 성적 해석

완료 전에는 이진 후보의 새 정확도·정상 오탐률을 만들지 않는다.
완료하면 같은 노출 합성 dev 54문항에서 아래 기존 관측과 비교한다.

| 기존 모델 | 정답률 | 정상 오탐률 | 오류 검출률 |
| --- | ---: | ---: | ---: |
| R1 | 26/54, 48.1% | 3/18, 16.7% | 11/36, 30.6% |
| 이전 구간 후보 | 35/54, 64.8% | 17/18, 94.4% | 34/36, 94.4% |
| 학습률 계획 수정 후보 | 36/54, 66.7% | 14/18, 77.8% | 32/36, 88.9% |

새 블라인드·실제 통신문 성적이 아니다. 근거 부족 규칙의 성공을 모델 성적에
더하지 않으며, 실제 문서의 사람 승인·자동 공개·운영 모델 교체는 하지 않는다.

## 실제 확인 결과

- 새 보호 경로를 수정 전 실패로 재현한 뒤 수정했다. 관련 테스트 **38 passed**.
- 최종 전체 회귀 **1022 passed, 3 skipped, 31.54초**. 기본 환경에 Torch가 없어
  별도 Torch 모듈 3개는 생략됐다. 기존 격리 Torch 환경에서 해당 모듈을 따로 실행해
  **11 passed, 1.59초**를 확인했다. 실제 후보 훈련으로 계산하지 않는다.
- `compileall`, `git diff --check` 통과. 읽기 전용 안전 리뷰 Critical/Important 0.
  새 optimizer 경계·발행 실패·영수증 직후 중단·성공 후 평가 완료 경로도 시험했다.
- 실행 시 실제 PLAN·저장 경계·원장 무결성 확인 통과. PLAN 변경은 컨트롤러 소스 pin
  하나뿐이며 JOB·학습 설정·자료·입력·기존 원장 바이트는 변하지 않았다.
- 추가 재개 허가를 등록하고 기존 자동 재확인을 활성화했다. 실제 `advance` 결과는
  **WAITING_RESOURCE**이며, 추가 발행 영수증은 아직 없고 허가는 미소진이다.
- 새 학습·새 성능 비교·운영 배포는 아직 완료되지 않았다. 자원 확보를 위해
  다른 앱·서비스를 종료하지 않았으며, 유료 API·외부 모델·새 후보를 사용하지 않았다.

## 확인·중지

기존 `com.moa.research`와 `moa-r2`가 같은 컨트롤러·장치 잠금을 사용한다.
새 cron·공개 포트·별도 훈련 프로세스 관리자는 만들지 않는다.
자원 대기가 지속되면 조용히 대기하고, 완료·실패·필수 조치만 알린다.

```bash
/Users/mac-mini/.local/bin/dev-storage run Relocated-20261017/work/moa-push -- .venv312/bin/python -m moa.research_cli status
/Users/mac-mini/.local/bin/dev-storage run Relocated-20261017/work/moa-push -- .venv312/bin/python -m moa.research_cli pause
```

비공개 자료는 `Cache/MOA/unattended-20261020/binary-training/`에만 보관한다.
원문·DB·학습자료·모델·비밀정보·비공개 실행 기록은 Git에 올리지 않는다.
