# MOA — 근거 규칙 분리와 실제 정상·오류 학습

## 결론

기존 정상 오탐 **77.8%(14/18)**는 여전히 너무 높다. 기존 연구는 학습 때
3범주(정상·오류·근거 부족)를 쓰고 평가에서만 두 선택지를 사용했다.
이번에는 **학습 입력·정답·손실의 선택지도 실제 두 개만** 쓰는 별도 경로를 구현했다.
근거 부족은 모델 정답으로 학습시키지 않고 독립적인 원본 취득 근거 검사로 분리한다.

코드·자료·실제 토크나이저 검증과 자동 대기열 등록을 완료했다.
**새 모델 훈련·저장·재로딩·성능 비교는 아직 실행하지 않았다.**
최신 사용자 요청으로 이번 이진 후보에만 별도 추가 1회를 등록했다.
기본 8회 + 이미 소진한 이전 학습률 후보 1회 + 이번 이진 후보 1회로,
이 작업에 한한 실효 후보 상한은 10회다. 기존 허용을 재사용하거나 원장을 초기화하지 않았다.
시간 예산은 충족하며 현재 상태는 15분 사용자 유휴를 기다리는 `WAITING_RESOURCE`다.

## 실제 바꾼 동작

- 연구 worker에 명시적인 `moa.binary-training.v1` 프로필을 추가했다.
  `preserved`/`changed` 두 실제 선택지만 만들며 세 번째 정답이나 선택지,
  질문 정의 불일치, 근거 미확보 상태는 거절한다. 기존 3범주 작업은 바꾸지 않았다.
- 원본 취득 파일 해시, 원본 구역, 필수 문맥, 표 헤더·각주·병합 inventory,
  확인된 파일 역할을 검사한다. 단순한 `source_complete=true`나 모델 답을 근거로 쓰지 않는다.
- 합성 원문의 독립 사실과 기록된 변형 연산을 다시 재생해 정답을 확인했다.
  실제 DOM 관측, 기존 자료와의 동일성, 권리와 train/dev 원문·양식 그룹 분리를 재검증했다.
- 직접 확인된 불일치를 모델의 정상 판정으로 덮어쓰지 않는 기존 근거 우선 경로를 유지한다.
- 실제 worker 입력 해시와 토크나이저 정답 위치를 검증한 뒤에만 향후 작업을 발행한다.
  규칙에 의한 근거 부족은 모델의 정답률에 더하지 않는다.

## 자료와 비교 범위

| 구분 | 정상 | 오류 | 모델 대상 합계 | 근거 규칙으로 제외 |
| --- | ---: | ---: | ---: | ---: |
| 합성 train | 36 | 72 | 108 | 36 |
| 노출 합성 dev | 18 | 36 | 54 | 18 |

train 12개 / dev 6개 원문·양식 그룹을 유지했다. 이번 자료는 **기존 허용 합성
train/dev의 파생본**이며 신규 독립 그룹 수는 0이다. 새 블라인드 또는 실물 성적이 아니다.
기존 blind·평가 전용 학교 원문·사람 미확인 자료를 학습에 옮기지 않았다.
정상/오류의 기존 1:2 구성도 그대로이며 복제·oversampling·임계값 맞추기는 하지 않는다.

규칙이 제외한 dev 18건은 따로 기록한다. 이 자료에서 단순히 모두 오류라고 해도
정답률 66.7%가 되므로 그 숫자만으로 개선을 선언하지 않는다.
직접 검사 대비 추가 오류 발견이나 실제 통신문 정답률은 이번 준비로 검증된 것이 아니다.

## 실행 계획과 원래 안전 한도

고정 작업: `moa-unattended-20261021-binary-train-01` **1개만**.

- 기존 비교와 동일한 격리 맥미니 CPU, R1 초기 가중치, seed, 4 epochs,
  batch/누적, encoder 동결, 초기 학습률 및 최소 학습률을 유지한다.
- 근거 부족을 뺀 108개를 4 epochs 처리하므로 실제 예정 업데이트는 **56회**다.
  선택지·정답 구성과 자료 제외에 따른 변화이며 이전의 학습률 단일 변수 시험과는 구분한다.
- 후보별 기존의 더 엄격한 **120 updates / 1800초**를 유지한다.
  업데이트를 채우려고 epoch를 늘리거나 자료를 복제하지 않는다.
- 훈련 후 별도 프로세스로 저장 모델을 재로딩하고 새 후보만 누적 **600초** 이내 평가한다.
  기존 후보의 평가 예산을 초기화하거나 재사용하지 않는다.
- 7일 8시간·기본 8후보, 하루 3시간, AC·15분 사용자 유휴·메모리 압력·가용 5GiB 검사를 유지한다.
  이번 명시 허가는 고정된 이진 작업 1개에만 후보 상한 10회를 적용한다.
  시작 시 1800초 전체를 예약할 수 있어야 한다.
- 알려진 저장 경계에서만 최대 4회 재개한다. 원래 예약 날짜를 넘는 재개,
  원인 불명 중단·변조·불명확한 상태는 `RECONCILIATION_REQUIRED`로 멈춘다.
- 원장의 기존 접두부 해시와 바이트 길이를 고정해 삭제·초기화를 거절한다.
  시간 예산을 늘리거나 소진된 9번째 후보 허용을 새 작업에 쓰지 않는다.

추가 허가 등록 시 사용량: 7일 **8775.63/28800초**, 오늘 **1800/10800초**, 후보 **9회**.
이 작업 전용 후보 잔여는 1이며, 1800초 전체 예약도 가능한 상태다.
기존 표준 한도 복귀 날짜까지 기다릴 필요는 없어졌지만 실제 학습은
자동 tick이 시간 예산과 자원 검사를 모두 통과할 때만 시작한다.
여기서 예산은 유료 API 비용이 아니라 기기 사용시간·실험 횟수의 안전 한도다.

## 자동 실행·보존·확인 명령

기존 시간별 `com.moa.research` 등록과 내부 tick 사본의 동일 해시를 확인했다.
기존 `moa-r2` heartbeat를 같은 단일 작업을 관찰하도록 갱신해 활성화했다.
새 cron·공개 포트·맥북 수동 전달 경로는 만들지 않았다. 상태가 변하지 않으면 반복 보고하지 않는다.
완료 또는 확인 필요 상태가 되면 앱 heartbeat를 정지하며 추가 후보를 자동 실행하지 않는다.

현재 계획은 `binary-training/PLAN.json`, 상태는 `STATE.json`, 실제 입력 검사는
`INPUT_PREFLIGHT.json`에 저장된다. 완료 후 같은 폴더에 `COMPARISON.json`과 `RESULT.md`를 만든다.
기존 계획·자료·원장·모델은 보존하며 NAS 운영 DB·원문·수집기·인증·승인·공개 설정에는 쓰기 작업을 하지 않았다.
운영 배포·모델 교체·사람 대신 승인·유료 API·Muse/JEV·모델 다운로드는 하지 않았다.

```bash
/Users/mac-mini/.local/bin/dev-storage run Relocated-20261017/work/moa-push -- .venv312/bin/python -m moa.research_cli status
/Users/mac-mini/.local/bin/dev-storage run Relocated-20261017/work/moa-push -- .venv312/bin/python -m moa.research_cli pause
/Users/mac-mini/.local/bin/dev-storage run Relocated-20261017/work/moa-push -- .venv312/bin/python -m moa.research_cli resume
```

비공개 실행 근거는 외장 SSD의 `Cache/MOA/unattended-20261020/binary-training/`에만 둔다.
Git에는 코드·테스트·비밀 없는 문서만 반영한다. 새 훈련 성적·완주·실제 통신문 품질·운영 적용은 미검증이다.
