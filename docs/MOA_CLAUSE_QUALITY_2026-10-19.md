# MOA 정상 문장 순서·표현 오탐 개선 — 2026-10-19

## 적용 범위

기존 프로젝트의 시험용 scoped 직접 검사기를 개선했다. LAYA/NLI 추론·추가 학습·유료 API 호출은 하지 않았다.
운영 배포, 운영 DB/schema, collector, 모델 registry, 자동 승인·공개와 실제 검수 기록도 변경하지 않았다.
이번 결과는 **저작한 합성 사실과 실제 Chrome DOM의 구역 비교**다. 실제 학교 통신문의 정확도가 아니다.

## 고친 원인

1. 독립적인 명명 필드를 일부 고정 접두어로만 인정하던 제약을 제거했다. 고유한 전체 필드명과 값의 대응이 필요하다.
2. `보증금: 7800원` / `보증금은 7,800원입니다`처럼 명시적인 서술형 필드 표현을 같은 값으로 비교한다.
   시각의 콜론을 새 필드 구분자로 잘못 해석하지 않는다.
3. 제한된 서술어의 `합니다/해요`, `하여야/해야`와 명확한 단일 긍정 의무 문장의 말투를 정규화한다.
   주어·대상·수량·부정·조건을 포함한 prefix 전체는 그대로 보존한다.
   명사 첫 글자를 수량사로 추측하지 않고 목적격 조사를 요구해 연결어 뒤 의무 전파를 차단한다.
4. 다른 단어 내부의 `상기`, `위`를 문장 간 참조라고 잘못 읽던 어휘 경계를 보완했다.
   실제 위/앞/아래 항목, 최상위·최하위 등 복합 위치 참조와 전자/후자 참조는 계속 엄격 비교한다.

전체 문장을 정렬하는 방식이 아니다. 원문과 DOM 각각에서 독립적으로 계산한 정규형,
고유 anchor, 모든 문장의 1:1 대응과 전체 토큰 일치를 요구한다. 원문 값을 DOM에 채워 넣지 않는다.
보고서에는 원래 토큰 일치와 정규형 일치, 실제 위치 대응, 양쪽에 적용한 rule ID를 구분한다.
동결된 기본 `moa/verification.py`, 근거 가드와 자료 생성 모듈은 변경하지 않았다.

## 안전상 허용하지 않은 표현

주어·목적어의 자리를 바꾸는 표현은 이번 문법으로 자동 인정하지 않는다. 검토 과정에서
수량 범위와 `만을/만은` 의미가 바뀌는데도 같다고 처리할 수 있음을 재현해 해당 경로를 제거했다.
부정·종속절의 `반드시`를 마지막 동작의 의무로 확대하지도 않는다.
`전자공학`처럼 참조어와 합성명사를 확실히 구별하지 못하는 경우도 보수적으로 남긴다.
따라서 모든 정상 한국어 재표현이 해결됐다는 뜻은 아니다. 미지원 표현은 검수 필요로 남는다.
