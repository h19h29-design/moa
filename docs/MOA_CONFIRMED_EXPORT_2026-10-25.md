# 확인 완료본 선택·비공개 묶음 다운로드 — 17단계, 2026-10-25

## 담당자 흐름

최종 검토·확인 뒤, 같은 학교의 최신 확인 완료본들을 골라 원본과 함께 내려받는다.

1. 학교별 검수 현황 또는 최종 확인 기록에서 **확인 완료본 선택·묶음 다운로드**를 연다.
2. 제목으로 찾고, 현재 페이지의 확인 완료본을 최대 10건 선택한다. 목록은 20건씩 표시한다.
3. **선택한 확인 완료본 준비**를 누르면 포함 문서·수신/검수 순서·담당자·시각·파일 수·
   분석 완전성·남은 경고 수를 보여 준다. 각 문서의 고정된 확인 기록·HTML도 열 수 있다.
4. 포함 범위를 직접 확인한 뒤 확인란을 선택하고 **확인한 묶음 ZIP 다운로드**를 누른다.
5. ZIP의 `index.html`에서 각 문서로 이동한다. 문서별 수정 HTML, 원본 파일, 근거 JSON을 포함한다.

확인된 정식 검수본만 사용한다. 개인 임시 입력이나 다른 탭의 미저장 입력은 반영하지 않는다.
경고·미확정 범위를 보존하며 문서 전체의 완전성 보증이나 공개 승인을 뜻하지 않는다.
JavaScript 없이도 선택·미리보기·다운로드가 가능하다.

## 버전·저장·권한 계약

| 경로 | 계약 |
|---|---|
| `GET /confirmed-export?q=…&page=…` | 내 학교의 최신 확인 완료 목록, 제목 검색·페이지 |
| `POST /confirmed-export/prepare` | 표시된 수신·변환·검수 ID를 검증하고 현재 로그인 세션에 준비 목록 보관 |
| `GET /confirmed-export/preview?bundle=…` | 같은 로그인에서만 고정 목록 재검증·조회 |
| `POST /confirmed-export/download` | 명시적 확인·권한·현재 버전·원본 무결성 재검사 후 ZIP 반환 |

- **DB schema·마이그레이션·테이블 추가가 없다.** 기존 학교 schema v6를 유지한다.
  모든 새 경로는 DB·원본·이전 검수 행·자동 분석·변환 HTML·개인 입력·큐를 쓰지 않는다.
  준비 목록에는 ID와 스냅샷 SHA256만 로그인 메모리에 보관한다.
- 목록은 로그인당 최근 4개까지 유지한다. 5번째 준비 시 가장 오래된 목록을 제거한다.
  세션 만료·로그아웃·서버 재시작 후에는 다시 선택한다. 장기 보관·공개 링크 기능은 아니다.
- reader도 기존 원본/HTML 다운로드 권한 안에서 이용한다. 학교·담당자는 인증 세션에서 결정한다.
  다른 학교 문서는 404, 다른 로그인 세션의 준비 ID도 404, 소속 해제·학교 비활성은 인증 단계에서 차단한다.
- 선택 시점의 수신·변환·최신 확인 이벤트와 전체 스냅샷 hash를 고정한다.
  준비 뒤 정정본·재변환·검수 수정·확인 취소·hash 변경이 있으면 최신본으로 자동 대체하지 않고 409로 중단한다.
  내려받기는 한 SQLite 읽기 시점에서 모든 선택 문서를 검증·출력한다.
  그 시점 이후의 동시 수정은 이미 시작한 출력에 섞이지 않으며 다음 요청에서 감지한다.
- 원본은 기존 단건 ZIP의 경로·일반 파일·크기·SHA256 검증을 재사용한다.
  원본 누락·변조·symlink·디렉터리·FIFO, 선택 문서 중 하나의 실패도 ZIP 전체를 중단한다.
  모든 문서 검증을 마친 뒤 응답 헤더/바이트를 보내므로 일부 문서만 빠진 ZIP은 반환하지 않는다.
- 파일명은 표시용 메타데이터로만 쓰고, ZIP 경로는 `documents/01/…`과 SHA 기반 원본 경로로 생성한다.
  상대 원본 링크, HTML hash, 원본 hash, 고정 버전과 경고를 문서별 `manifest.json`에 보존한다.
  루트 근거에는 문서 목록·고정 스냅샷 hash·목록 HTML hash·비공개 상태를 기록한다.
  이전 검수본의 개별 HTML/ZIP은 계속 같은 바이트로 내려받을 수 있다.
- 최대 10건, 원본 합계 64MiB, HTML/근거/루트 목록을 포함한 ZIP 내용 합계 96MiB이다.
  단건의 기존 10파일·파일당 25MiB·원본 총 50MiB 제한도 유지한다.
  압축 해제나 중간 파일 저장 없이 메모리에서 문서별 패키지를 순차 처리한다.
  한도 초과는 문서를 나눠 선택하도록 안내하고 DB나 파일을 남기지 않는다.
- POST는 16,384바이트, GET query는 4,096자로 제한한다.
  CSRF·Origin·중복/추가 필드·잘못된 UTF-8·선택 ID 형식·중복 문서·명시적 확인을 검사한다.
  HTML/파일명/작성자/경고를 escape하고 기존 인증·CSP·no-store 정책을 유지한다.
  새 모델·parser·변환 작업·공개 승인·학습 작업을 시작하지 않는다.
