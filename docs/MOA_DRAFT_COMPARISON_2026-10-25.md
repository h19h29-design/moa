# 임시 입력과 현재 검수본 비교 — 12단계, 2026-10-25

## 개발 범위와 담당자 사용법

11단계 자동 임시저장에 이어 저장된 입력을 현재 검수본과 대조하는 기능을 구현했다.
이전에는 오래된 초안을 원시 데이터로만 확인할 수 있었다. 이제 변경된 기준과
저장한 구역·관계 입력을 읽기 전용으로 확인할 수 있다. 자동 병합·적용 기능은 추가하지 않았다.

1. **내 임시 저장 입력 → 현재 검수본과 비교**를 연다.
   복구한 입력 화면과 오래된 초안의 읽기 전용 화면에서도 비교로 이동할 수 있다.
2. 현재 검수본의 구역 종류·텍스트와 개인 임시 입력을 나란히 확인한다.
   사유는 개인 초안의 입력이며 현재 정식 검수 사유로 오인하지 않도록 따로 표시한다.
   미완성 관계는 종류·출발/대상 ID와 현재 같은 관계의 개수·ID 존재 여부를 확인한다.
3. 권한·기준·최신 개인 입력이 모두 일치할 때만 **이 입력 복구·검수 계속하기**를 제공한다.
   복구는 기존 항목 폼을 채울 뿐 정식 검수·확인·HTML 반영이 아니다.
4. 더 최신 개인 입력, 정식 검수 변경, 정정 수신본, 재변환 진행/실패/새 변환,
   조회 권한 전환, 구조 기준 변경·누락을 구분해 표시한다. 이전 입력은 그대로 보존한다.
   최신 개인 입력 비교·최신 수신본 확인·비교한 검수 시점으로 이동할 수 있다.

## 동일 기준·읽기 전용 계약

- 신규 `GET /structure-draft/compare?id=<개인 초안 ID>`는 로그인한 학교·담당자 소유권을 모두 검사한다.
  같은 학교의 다른 수정권한 담당자도 타인의 개인 입력을 열 수 없다. 권한 회수는 기존 세션 검사로 차단한다.
- SQLite `SAVEPOINT` 안에서 소속/권한·불변 초안·최신 개인 입력·정정 수신본·변환·정식 검수를 읽는다.
  조회 중 별도 연결에서 정식 검수가 바뀌어도 서로 다른 시점을 혼합하지 않는다.
  조회 뒤 변경된 권한·기준은 기존 복구/정식 저장에서 다시 검사한다.
- **저장 당시 수신본·변환 버전**의 현재 정식 검수만 비교한다.
  정정본이나 재변환이 생겨도 구역 ID를 새 버전에 대응시키지 않는다.
  이전 수신/변환의 비교라는 제목·경고와 최신 수신본 링크로 이 경계를 표시한다.
- 자동 분석 hash가 달라지거나 대응 항목/구조가 없으면 현재 항목을 잘못 붙이지 않는다.
  저장 입력만 표시하고 비교 불가·복구 중지를 알린다. 내부 오류 상세를 출력하지 않는다.
- 비교 시점의 정식 검수 링크는 수신본·변환·검수 이벤트를 고정한다.
  정식 검수가 없던 경우는 고정 수신본/변환의 자동 분석본 링크를 사용한다.
- 텍스트는 기존 선형 공통 접두/접미 비교를 재사용한다. 차이가 있는 가운데 범위를 강조하며
  최소 단어 단위 편집·자동 적용 결과라고 부르지 않는다. 공백·개행을 정규화하지 않는다.
- 기존 v4 초안 스키마를 재사용한다. DB 스키마·마이그레이션·POST 저장 계약·자동저장 JS 변경은 없다.
  비교 GET은 초안/검수/작업 큐/재개 위치를 쓰거나 마이그레이션하지 않는다.
- 쿼리는 `id` 하나·4,096자 이내로 제한한다. 중복/추가 필드·잘못된 UTF-8/ID를 거부한다.
  HTML escape, 인증, `no-store`, 기존 CSP를 유지한다. 새 JSON·다운로드·공개 API는 없다.
  문서 본문을 실행하지 않으며 JavaScript 없이도 비교/복구 링크가 작동한다.
