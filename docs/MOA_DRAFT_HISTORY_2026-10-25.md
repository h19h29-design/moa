# 개인 임시 입력 버전 이력·비교 — 13단계, 2026-10-25

## 담당자 사용 흐름

12단계의 현재 검수본 비교에 이어, 자동·수동 임시저장으로 보존된 이전 입력을
조회하고 두 개인 저장본의 차이를 확인할 수 있다.

1. **내 임시 저장 입력 → 임시 입력 버전 이력**을 연다.
   기존 현재 검수본 비교·복구된 편집 화면·오래된 읽기 전용 입력에서도 연결된다.
2. 같은 담당자·수신본·변환·항목의 이력을 최근 순서로 20개씩 확인한다.
   목록에는 번호·시각·최신 여부만 표시하고 입력 본문·사유는 펼치지 않는다.
3. 현재 페이지에서 **기준 임시 버전 / 대상 임시 버전**을 골라 비교하거나,
   각 저장본의 **직전 임시 버전과 비교**를 연다. 직전 비교는 페이지 경계에서도 작동한다.
   기준 번호는 대상보다 작거나 같아야 한다. 같은 버전도 확인할 수 있다.
4. 구역 종류·텍스트·개인 사유, 또는 관계 종류·출발/대상 ID·사유를 나란히 본다.
   미완성 관계의 빈 ID·공백·개행은 그대로 보존한다. 관계의 유효성 판정은 아니다.
5. 두 입력 사이에 정식 검수 또는 구조 기준이 바뀌면 경고한다.
   **이 입력과 현재 검수본 비교**로 이동하면 기존 12단계가 복구 가능 여부를 다시 검사한다.

이는 개인 임시 입력 이력이다. 정식 검수·확인·HTML 반영 이력과 구별하며,
과거 입력 자동 복구·병합·현재 기준으로 재저장·자동 승인은 추가하지 않았다.
변경 강조는 선형 공통 접두/접미 방식의 가운데 차이이며 최소 단어 편집 결과가 아니다.

## DB·권한·조회 계약

| 경로 | 계약 |
|---|---|
| `GET /structure-draft/history?id=…&page=…` | 선택 ID의 순번까지 이력을 고정하고 20개씩 메타데이터 조회 |
| `GET /structure-draft/diff?before=…&after=…` | 동일 범위의 불변 개인 스냅샷 2개만 비교 |

- 기존 v4 `school_review_drafts`와 인덱스·불변성 trigger를 재사용한다.
  스키마·마이그레이션·저장 POST·자동저장 JS는 변경하지 않았다.
- 학교/담당자/수신본/변환/항목을 모두 일치시킨다. 다른 학교뿐 아니라 같은 학교의
  다른 manager도 개인 입력을 볼 수 없다. 두 저장본의 동작 종류도 같아야 한다.
- 로그인·활성 소속·학교 활성 상태를 매 요청 검사한다. 본인의 reader 권한은 읽기만 허용한다.
  기존 `no-store`, CSP, HTML escape와 GET 비변경 계약을 유지한다.
- 각 조회는 SQLite SAVEPOINT의 한 읽기 시점으로 권한·선택 저장본·최신본·페이지를 읽는다.
  조회 도중 자동저장이 발생해도 페이지 번호·행 순서가 밀리지 않는다.
  새 저장본은 **최신 임시 입력까지 이력 보기**로 명시적으로 이동한다.
- 같은 항목이라도 정정 수신본/새 변환으로 이력을 섞지 않는다.
  원본 구조를 다시 읽거나 파싱하지 않아 재변환·구조 조회 실패 후에도 저장 입력을 확인할 수 있다.
- 쿼리는 4,096자, ID는 32자리 hex, 페이지는 1~1,000,000으로 제한한다.
  중복/추가 필드·잘못된 UTF-8·누락/잘못된 ID를 거부한다. 두 ID를 조회 전에 검증한다.
  알려지지 않은 저장본/소유/범위는 404, 잘못된 ID/페이지/역순 비교는 400이다.
- 목록은 최대 20행, 비교는 저장 길이 제한을 이미 통과한 2개 입력만 렌더링한다.
  브라우저 영구 저장소·새 외부 요청·JSON 다운로드·의존성·백그라운드 작업은 없다.
