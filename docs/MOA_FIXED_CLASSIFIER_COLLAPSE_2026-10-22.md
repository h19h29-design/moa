# 고정 분류기 전부 오류 판정 — 원인 진단과 미발행 수정안

## 결론과 현재 한계

기존 후보가 내용 차이를 학습한 것이 아니라 **전체 출력이 다수 클래스 쪽으로 이동한 붕괴**임을
맥북의 저장 모델로 확인했다. 최종 모델은 노출 합성 dev54뿐 아니라 **train108도 전부 오류**로 판정했다.
정확도 66.67%는 오류 비중 2/3과 같고 정상 오탐률은 100%, 균형 정확도는 50%다.
단순히 학습 시간이 부족해서 정상 자료를 아직 보지 못했다거나, 정상/오류 출력 인덱스가 뒤집힌 경우는 아니다.

수정 방향은 같은 무가중 학습 반복이 아니라 **정상/오류의 총 학습 손실 비중을 같게 만드는 목적 함수**다.
새 함수와 한쪽 답만 내는 결과를 실패로 식별하는 진단 검사를 추가했다.
다만 이는 **미발행 연구 수정안**이다. 실제 모델의 오탐률이 개선됐다는 결과가 아니다.
원래 완료 후보·모델·봉인 worker에 소급 적용하지 않았고, 새 후보 잔여 0개이므로 추가 학습을 하지 않았다.

## 1. 재현 및 원인 분리

기존 54개 원판정 영수증을 다시 집계하는 최소 재현은 정상 사례도 정상이 나와야 한다는 검사에서 실패했다.
이 재집계는 모델 실행이 아니다. 정상18/오류36 모두 오류로 나왔으며,
정상과 오류의 평균 오류 확률은 각각 **0.681432 / 0.682863**으로 거의 같았다.
학습 비율만 나눠 사후 보정해도 이번 고정 분류기의 판정은 모두 오류 그대로다.
개발 정답으로 임계값을 찾거나, 답을 반대로 뒤집는 처방은 적용하지 않았다.

읽기 전용 원본 검사에서 다음을 확인했다.

- 실제 target은 정상0/오류1이고 저장·재로딩의 label mapping과 일치한다.
- train108은 정상36/오류72이며 동일한 직렬화 입력에 반대 정답이 붙은 충돌은 0개다.
- 0/8/28/56 업데이트의 저장 optimizer·scheduler·history가 이어진다. 8-update prefix도 일치한다.
- 최종 판단부 값은 유한하며 실제 56 updates가 저장돼 있다. 가중치 미갱신이나 중간 초기화의 증거는 없다.
- 기존 tokenizer 사전검사는 162건, 최대768tokens, 잘림0이다. 이번에 그 입력·정답·학습 설정을 바꾸지 않았다.
- 고정 encoder의 train flag는 켜지지만 실제 nonzero Dropout module은 0개, attention dropout도 0이다.
  따라서 이 실행의 원인을 단순한 encoder dropout 모드 문제라고 단정하지 않는다.

## 2. 맥북 저장 체크포인트 진단

추가 학습 없이 실제 저장한 head만 순서대로 재로딩했다. 원래 R1 encoder와 모델·입력 해시를 검증하고,
optimizer를 생성하거나 가중치를 바꾸지 않았다. 맥미니는 제어와 집계만 수행했다.

| 저장 시점 | 진단 입력 | 실제 판정 |
| --- | --- | --- |
| 0 updates | 동일한 정상6/오류6 학습 사례 | 12건 전부 정상 |
| 8 updates | 위와 같은 12건 | 12건 전부 정상 |
| 28 updates | 위와 같은 12건 | 12건 전부 오류 |
| 56 updates | 전체 train108(정상36/오류72) | 108건 전부 오류 |

초기 정상 확률 편향을 내용 구분으로 해결한 것이 아니라 반대편 오류 편향으로 바꿨다.
초기/중간12건과 최종108건은 개수가 다른 **학습 적합 진단**이며,
서로 같은 표본의 정확도 상승 곡선이나 독립 평가 성적으로 해석하지 않는다.

최종 train의 평균 오류 확률은 정상 **0.680650**, 오류 **0.682595**다.
train 전체 cross entropy는 **0.635067**이며,
내용을 무시하고 오류 확률을 항상2/3로 내는 기준은 **0.636514**다.
같은12건의 판단 직전 표현 상대변동은0-update **0.062088**에서 최종 **0.002011**로 줄었다.
이 지표는 표현의 중심 크기로 정규화한 보조 통계이며 그 자체만으로 특정 계층의 인과를 확정하지 않는다.

**확정된 실패 형태**는 train/dev 모두 내용 판별 실패와 클래스 편향이다.
**확인된 기여 요인**은 정상보다 오류가2배 많은 자료와 무가중 cross entropy가
상수 오류 확률2/3을 최적점으로 허용한다는 점이다.
고정 encoder의 CLS 정보 부족, 이전 선택지 판단부에서 CLS 분류로 전환한 효과,
학습률/표현 압축 중 무엇이 내용 신호를 약하게 만든 주원인인지는 분리되지 않았다.
따라서 클래스 비중만 바꾸면 반드시 해결된다고 주장하지 않는다.

## 3. 수정한 코드와 검증 범위

`moa/research_classifier_objective.py`에 train 빈도로만 정하는 가중치
`N / (2 * class_count)`를 추가했다. 정상36/오류72에서는 **정상1.5 / 오류0.75**이며
전체 정상 손실 질량과 오류 손실 질량이 각각54로 같다. dev 정답·출력은 가중치 계산에 쓰지 않는다.

현재 microbatch=1이므로 단순히 `cross_entropy(weight=..., reduction='mean')`을 쓰면
분모의 target weight가 그 가중치를 상쇄한다. 새 함수는 `reduction='none'`의 각 손실에
가중치를 곱한 뒤 평균하므로 기존 accumulation-window 평균에서도 보정 효과가 남는다.
기존 봉인된 학습 함수와 optimizer/scheduler는 변경하지 않았다.

맥북의 작은 tensor 검사에서 원래 목적 함수의 상수 오류 확률2/3은 bias gradient가0이지만,
새 목적 함수에서는 오류 logit gradient가 **+1/6**이라 하강 방향이 정상 오탐을 줄이는 쪽임을 확인했다.
미니배치1 가중치 유지·누적 gradient 일치·입력 유효성 등 **5개 테스트(잘못된 입력5종 subtest 포함)**를 통과했다.
테스트는 모델을 적재하지 않으며 optimizer step0, 연구 모델 호출0이다.
이 검증은 실제 모델의 정확도/오탐률 개선을 증명하는 학습 실험이 아니다.

`moa/research_classifier_diagnosis.py`의 별도 재집계는 원판정을 보존하면서
한쪽 클래스 붕괴, 균형 정확도, 정상 오탐, 양쪽 recall, 확률 범위와 AUC를 드러낸다.
한쪽 답만 내면 최소 내용 구분 검사를 통과하지 못한다.
그 최소 검사를 통과해도 운영 승인이나 충분한 성능을 뜻하지 않는다.
전부 정상으로 뒤집어 오류 recall을0으로 만드는 경우도 실패로 식별한다.

## 다음에 필요한 승인

**수정한 목적 함수의 실제 효과 검증은 별도 연구 후보1개를 필요로 한다.**
이미 완료된 후보를 다시 미완료로 바꾸거나 이전 추가 허가를 재사용하지 않는다.
사용자가 후보 수 예외1개를 별도로 허용한다면, 기존 일일/주간 시간·메모리 한도를 늘리지 않고
같은 R1/자료/seed/56updates/4epochs/배치/encoder동결/학습률에서 **손실 함수만** 비교한다.
학습·재로딩 평가는 맥북에서만 하며 한쪽 판정 붕괴 또는 정상 오탐 개선 실패 시 채택하지 않는다.
그 전에는 새 worker 발행·학습 예약·학습 실행을 하지 않는다.
