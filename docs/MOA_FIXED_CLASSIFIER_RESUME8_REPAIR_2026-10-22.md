# 저장 8-update 분류기 — 게이트웨이 제어 수정과 1회 재개 결과

## 승인 범위

사용자가 2026-10-22 명시 허용한 동일 고정 분류기
`moa-unattended-20261021-fixed-classifier-01`를 저장 8 updates부터 1회 이어갔다.
새 후보·새 시간·원장 초기화가 아니다. 맥미니는 제어·집계만, 실제 학습·평가는 맥북 MPS만 사용했다.
원래 0-update/8-update 체크포인트·실패한 제어 시도·허가·종료 상태를 보존했다.
과거 누적 51.057159초를 제외한 잔여 1748.942841초, 별도 재로딩 평가 600초를 유지했다.
train108/dev54·고정 2출력·4 epochs/56 예정/120 최대 updates·동결 R1 인코더·seed·배치·학습률은 불변이다.
학습 전 7GiB/실행 중 5GiB, AC·15분 유휴·메모리 압력·디스크·device.lock·원래 KST 예약일,
주간 8시간/하루 3시간 제한도 낮추지 않았다.

## 확인된 원인과 수정

실제 맥북에서 모델 호출 없는 재현 검사를 했다. 성공한 bootout 명령 뒤에도 두 서비스가
약 5초간 등록된 `SIGTERMed` 상태로 남았다. 기존 구현은 즉시 등록 여부를 확인해 실패로 판정했다.
복구도 그 시점에 kickstart를 한 번만 보내고 이후에는 상태를 읽기만 했다.
5초 뒤 서비스가 실제로 사라져도 bootstrap을 다시 하지 않아 복구 의무가 남았다.
같은 실제 명령 경로의 재현 검사는 실패했고, 별도 정상 복구로 두 서비스를 되살렸다.

수정은 등록 해제 완료까지 제한 시간 안에서 상태를 확인하고, 복구 중에도 관찰된 상태에 따라
enable/bootstrap/kickstart를 조정한다. 승인된 정확한 두 label/plist만 취급한다.
명령 제출 성공을 실제 종료·복구 완료로 계산하지 않는다. 원래 봉인 소스는 수정하지 않았고,
얇은 새 어댑터가 검증된 기존 학습·재로딩 알고리즘을 그대로 사용한다.

맥북의 실제 수정 후 검사는 중지→기존 감시기와 같은 bootstrap/kickstart 시도→중지 유지→
원래 enabled·포트·HTTP 200 복구를 모두 통과했다. 장애 재현과 이 검사는 연구 모델 호출 0이다.
감시기 자체·설정·인증은 변경하지 않았다. 훈련용 중지 전 별도 준비 응답을 한 복구 guardian과
복구 의무 영수증을 사용하며, 종료·안전 중단·평가 완료 시 원상복구한다.

## 맥북 정리

사용자의 다른 작업 종료 지시에 따라 Paperclip 개발 LaunchAgent를 정상 bootout했다.
강제 kill·DB/파일 삭제·전역 캐시 정리는 하지 않았고, 원래 plist를 보존했다.
일반 브라우저·Codex GUI 본체는 실행 중이 아니었다. macOS 필수 기능·원격 연결·절전 방지는 유지했다.
승인된 두 OpenClaw 게이트웨이를 일시 disable/bootout했고, 그 외 보호 시스템 서비스를 건드리지 않았다.
Paperclip은 사용자 지시대로 중지 상태를 유지한다. 아래 두 게이트웨이는 평가 후 복구했다.

## 검증

- 실제 비동기 SIGTERMed 상태를 재현한 회귀 2개가 기존 구현에서 실패한 뒤 수정 후 통과했다.
- 수정 관련 단위 검사와 전체 회귀 1195 passed / 11 skipped(33.08초)를 실행했다.
- 맥북의 저장 상태 복원용 작은 CPU 텐서 5개 검사를 통과했다. 실제 연구 학습/평가와 구분한다.
- 새 제어·worker·게이트웨이 모듈의 컴파일을 확인했다.
- 별도 읽기 전용 코드 검토에서 확인된 Critical/Important 문제는 없었다. 해당 검토는 테스트 재실행이 아니다.
- 원장SHA256 `b275025bb7595cde5a9203b412fe516ff0f99618e47927e3e2981b094569e13d` 불변,
  기존 캠페인의 PAUSED 마커와 `moa-r2` 자동화의 PAUSED를 확인했다.

## 결과

상태는 **COMPLETE**다. 저장 8→56 updates, 즉 이번에 48 updates를 1회 수행했다.
이번 학습은 **248.775920초**, 이전 실제 시도를 포함한 누적은 **299.833079 / 1800초**다.
최종 저장 뒤 맥북의 별도 프로세스에서 head와 optimizer 저장 상태의 일치를 확인하고
head를 실제 재로딩했다(`reload_exact=true`). 평가는 **31.990318 / 600초**이며,
중복 없는 54개 case를 각 1회 판정했고 평가 중 학습 업데이트는 0이다.
학습 중 최저 가용 메모리는 **5.263885GiB**, 평가 중에는 **6.241333GiB**였다.

### 같은 노출 합성 dev54에서의 비교

정상 18건/오류 36건이다. 기존 선택지 모델은 실제 두 선택지 순서의 확률 평균으로 얻은
동결된 기존 결과이며 이번에 재실행하지 않았다. 새 고정 분류기만 선택지 없이 case당 1회 판정했다.

새 블라인드·실물 성적이나 운영 검증이 아니다. 평가 후 임계값 조정도 하지 않았다.

각 loopback 포트와 HTTP 200, 원래 plist SHA256의 일치를 확인했다. 자동 재시작 보류도 해제됐다.

- MODEL_REGISTRY / MODEL_MANIFEST / DEPLOYMENT_MANIFEST와 기존 R1/이진 모델 해시는 불변이다.
- 원래 0/8-update 저장 상태, 허가·예약·원장·봉인 소스 검증을 다시 통과했다.
