## 2. 실제 맥북 입력 감사

`scripts/moa-book-pilot.py`의 기존 `prepare_training_rows`를 재사용했다.
`scripts/moa-book-input-audit.py`는 맥북에 설치된 LAYA의 학습 인코더와 실제 Agent 인코더를
가중치 로딩 없이 호출해 다음을 대조한다.

- state·질문·instruction·선택지 순서와 실제 `input_ids`, `attention_mask`, 질문 위치·마스크·종류.
- semantic gold ID에서 실제 target index로의 연결. 선택지 순열 6가지도 확인.
- 설치된 워커 `ml.predict_payload` 호출의 실제 길이 인자와 checkpoint 설정·option layout.
- 전체 checkpoint manifest 파일 해시 맵(base 7개/이전 후보 6개), tokenizer와 설치 코드 해시.
- JSON 입력뿐 아니라 실제 질문별 토큰 입력을 기준으로 정답 충돌·split 교차.

결과: 1,000문항 일치, 실제 토큰 입력 1,000개 고유, 충돌·split 교차 0건,
최대 길이 294토큰, 잘림 없음. 유효 설정은 1024/256/sequential이며 학습 설정과 일치했다.
전처리는 새 프로세스에서 다시 생성했고, 저장된 item 캐시는 소비하지 않았다.
기존 캐시를 전부 삭제했다고 주장하지 않는다.

독립 코드 검토에서 발견된 고정 설정 비교와 토큰 충돌 검사 누락을 보강했다.
비정규 선택지 순서를 거부 없이 받으면서 잘못된 고정 index를 보고할 수 있던 helper도 수정했다.

## 5. 테스트·배포·남은 일

이번 실제 실행: 회귀 테스트 **257개 통과(16.99초)**, 관련 22개 통과,
Python compileall과 `git diff --check` 통과. 과거 249개 숫자를 재사용하지 않았다.

NAS collector/review는 기존 실행 이미지·환경·DB를 유지했다. 변경은 입력 감사·실험 합의·
위험률 집계이며 NAS 앱·DB 스키마를 바꾸지 않아 불필요한 재배포·마이그레이션은 하지 않았다.
맥북에도 감사/인계 파일만 전달했고 상시 워커 실행 파일·모델 포인터를 교체하지 않았다.
유료 API, 자동 파인튜닝, 모델 자동 교체, 자동 공개는 실행하지 않았다.

남은 것은 맥북 Codex의 S1/R1 실행·원자 저장·새 프로세스 재로딩·동일 입력 평가 영수증을
받아 base/이전 후보/새 후보를 비교하는 일이다. 실패하면 부분 완료 분모를 그대로 보고한다.
실행 결과가 없으므로 ‘수정 후에도 개선이 없다’고 결론내리지 않는다.

R1까지 개선이 없다면 자동 재학습하지 않는다. 다음 비교 변수 후보는 **loss의 클래스 가중치**
하나다. changed 비중이 55%인데도 기존 후보의 changed recall은 17/110이고 정상 오판이
64건이므로, 오류를 정상으로 넘기는 손실의 비대칭을 먼저 분리해 볼 근거가 있다.
효과를 확정한 것이 아니며 encoder·데이터·학습률을 동시에 바꾸지 않는다. 후속 실행은
별도 범위·자원 합의 없이는 시작하지 않는다.

비공개 근거는 `/Volumes/KIOXIA-2TB/Cache/MOA/recovery-20261018/`에 있고 Git 대상이 아니다.
PR #1을 기존 브랜치에서 정상 갱신하며 force push·main 자동 병합은 하지 않는다.
