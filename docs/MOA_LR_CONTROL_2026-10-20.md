## 자동 실행과 예산 보호

- 기존 `com.moa.research` 시간별 LaunchAgent를 재사용한다. 실제 등록 상태,
  실행 간격 3600초, 18회 실행, 마지막 exit 0을 확인했다.
- 기존 앱 heartbeat `moa-r2`를 이번 작업으로 갱신해 활성화했다. 15분 간격으로 같은
  단일 컨트롤러를 호출하며 새 LaunchAgent/cron/공개 포트를 만들지 않았다.
- 컨트롤러 잠금·기존 `device.lock`·단일 run_id·영수증 상태로 중복 발행을 막는다.
- 기존 7일 누적 8시간/8후보, 하루 3시간, 후보별 45분/400업데이트 상한을 유지한다.
  이번에는 더 작은 **1800초 전체 예약**이 가능할 때만 후보를 한 번 발행한다.
- AC/유휴/메모리 등 기존 런타임 보호에 더해 시작·재개 전 가용 메모리 5GiB를 요구한다.
  자원이 없으면 후보 예산을 차감하기 전에 대기한다.
- 알려진 자원/일시중지 경계만 최대 4회 재개한다. 동일 경계 반복·원인 불명 중단·
  체크포인트/입력/코드/정책 변경은 자동 재시도하지 않는다.
- 재개가 최초 일일 예약 날짜를 넘어가면 중단해 확인한다. 과거 예약을 새 날짜로 옮기거나
  원장을 지워 일일 한도를 우회하지 않는다. 저장된 누적 훈련시간 상한도 유지한다.
- 체크포인트는 저장 후 별도 평가 프로세스에서 실제 재로딩한다. 이 새 후보의 평가만
  누적 최대 600초이며 과거 후보의 사용 완료된 평가 예산은 그대로 둔다.
- 완료 후 다른 후보를 학습하지 않는다. 완료 또는 확인 필요 상태에서 heartbeat도 중지한다.
  시간별 로컬 tick이 남아 있어도 단일 작업의 완료 상태를 반환하며 다시 학습하지 않는다.

실행 전 구현 보강 중 아직 발행되지 않은 계획의 코드 pin을 갱신했고, 이전 PLAN/STATE와
변경 이유를 private 폴더에 보존했다. 학습 설정·입력·run_id·예산은 바꾸지 않았다.
이후 pin이 달라지면 자동으로 덮어 맞추지 않고 `RECONCILIATION_REQUIRED`로 멈춘다.
