# MOA 학습률 비교 — 이번 후보 1개만 추가 허용

기준 요청: 2026-10-20. 실행 확인은 한국시간 2026-10-21에도 이어진다.

## 현재 상태

사용자가 허용한 추가 후보 1개를 고정 작업
`moa-unattended-20261020-lr-schedule-01`에만 등록했다.
한국시간 **2026-10-21 00:07:24**, 후보·시간·메모리·AC 및 기존
**15분 사용자 유휴 조건**을 모두 통과해 실제 훈련을 발행했다.
**00:12:35에 저장·별도 재로딩·평가까지 `COMPLETE`**로 완료했다.
새 후보의 1800초 예약은 정확히 1건이다.
기존 원장 항목은 삭제·변경하지 않고 이 예약만 덧붙였다.

정답률은 이전 후보보다 1문항 올랐고 정상 오탐은 3건 줄었지만, 실제 오류를
2건 더 놓쳤다. 정상 오탐이 여전히 77.8%이므로 실용적인 품질 개선이나 운영
적용 성공으로 보지 않는다. 추가 훈련과 운영 교체는 하지 않았다.

전역 정책과 기존 예산 원장은 변경하지 않았다. 원래 7일 8후보 정책을
모든 작업에 9후보로 늘린 것이 아니라, 이번 고정 계획에만 9번째 자리를 허용한다.
추가 허용은 한 번만 사용하며 완료·실패한 후보를 다시 초기화하지 않는다.

## 바꾸는 변수와 유지하는 제한

- 이전 후보와 같은 R1 초기 가중치, 합성 train/dev, 입력, seed, 선택지 셔플,
  encoder 동결, 초기 학습률, epoch, batch와 격리 맥미니 CPU를 사용한다.
  이전 비교 대상이 맥미니 CPU에서 실행됐으므로 장치도 고정한다.
- 변경 변수는 scheduler의 `planned_updates` **120 → 72** 하나다.
  실제 데이터로 끝나는 업데이트 수는 이전과 같은 72다.
- 7일 훈련 8시간, 하루 3시간과 기존 후보별 상한은 그대로다.
  이번 후보는 더 작은 **120 updates/1800초** 제한을 유지한다.
  시작 전에 1800초 전체를 예약할 수 있어야 한다.
- AC, 15분 유휴, 메모리 압력 및 시작·재개 시 가용 메모리 5GiB 검사를 유지한다.
- 알려진 저장 경계에서만 최대 4회 재개한다. 최초 예약 날짜를 넘기거나
  원인 불명 중단·설정/해시 변경이 생기면 확인 필요 상태로 멈춘다.
- 저장 후 별도 프로세스로 재로딩해 새 후보만 누적 600초 이내 평가한다.
  기존 후보의 사용 완료된 훈련·평가 예산은 되돌리지 않는다.

## 비교 방법

기존에 노출된 합성 개발 **54문항(정상 18 / 오류 36)**을 사용한다.
실제 두 선택지 순서를 각각 실행하고 두 순서 평균과 순서별 결과를 남긴다.
표의 평균 결과는 순서별 라벨 확률을 평균한 후 최종 라벨을 고른 값이다.
R1과 이전 후보의 고정된 동일 입력 결과를 보존하고 새 후보만 같은 경로로 평가한다.
새 블라인드 또는 실제 학교 통신문 성적이 아니다.
규칙으로 강제한 답을 모델 정답으로 더하거나 평가자료로 임계값을 조정하지 않는다.

| 모델 | 정답률 | 정상 오탐률 | 실제 오류 검출률 |
| --- | --- | --- | --- |
| R1 (기존 결과) | 26/54, 48.1% | 3/18, 16.7% | 11/36, 30.6% |
| 이전 구간 후보 (기존 결과) | 35/54, 64.8% | 17/18, 94.4% | 34/36, 94.4% |
| 학습률 계획 수정 후보 | **36/54, 66.7%** | **14/18, 77.8%** | **32/36, 88.9%** |

정상 오탐만 줄고 실제 오류를 놓치는 경우도 함께 보고한다.
개선되지 않아도 다른 후보를 추가 학습하거나 운영 모델을 교체하지 않는다.

이전 후보 대비 정답률 **+1.9%p**, 정상 오탐률 **−16.7%p**,
실제 오류 검출률 **−5.6%p**다. 정상 오탐은 17→14건, 오류 미검출은 2→4건이다.
미완료·입력 초과는 0건이며 규칙 강제 판정은 이 점수에 포함하지 않았다.

| 실제 선택지 순서 | 새 후보 정답률 | 정상 오탐 | 실제 오류 검출 |
| --- | --- | --- | --- |
| 기본 순서 | 34/54, 63.0% | 16/18, 88.9% | 32/36, 88.9% |
| 역순 | 35/54, 64.8% | 13/18, 72.2% | 30/36, 83.3% |
| 라벨별 확률 평균 | 36/54, 66.7% | 14/18, 77.8% | 32/36, 88.9% |

순서가 바뀌면 13/54문항의 답이 달라졌다(이전 후보 8/54).
정상/오류 균형 정확도는 55.6%, 점수 순위 AUC는 0.519다.
전체 정답률 66.7%는 이 자료에서 모든 문항을 오류라고 찍는 기준과 같다.
따라서 학습률 일정만 수정해 의미 구별과 선택지 편향을 해결했다고 볼 수 없다.

## 실제 훈련·저장·재로딩

- 예정된 **72 optimizer updates / 4 epochs**를 **261.64초(약 4분 22초)**에 마쳤다.
  `epoch_limit`으로 정상 종료했고 재개·별도 후보는 0회다.
- 가중치 변경, 40회 중간 저장, 최종 모델 및 optimizer/scheduler/RNG 상태 저장을
  확인했다. 파일 해시와 실제 실행 설정 계약도 검증했다.
- 별도 프로세스에서 최종 모델을 실제 재로딩하고 **108회 입력(54문항×2순서)**을
  **33.75초**에 평가했다. 평가 프로세스에서는 학습하지 않았다.
- 새 모델 SHA-256:
  `d35e873258a7519b79b3e1cfc6b84f4771422c14cc39ad18c12bb7a180d039cc`
- 저장된 학습 상태 SHA-256:
  `9437954d504e6d29a6793aec08340745624ec819524fd5e37df02b32226f870a`
- 훈련 중 확인한 가용 메모리는 5.76~6.03GiB였고 메모리 압력 보호도 정상이었다.
  이는 일부 시점의 관측값이지 전체 실행의 최소 메모리 측정값은 아니다.

실제 훈련은 261.64초였지만 보수적인 원장의 **1800초 예약을 환급·축소하지 않았다**.
완료 당시 7일 원장 사용량은 8775.63초/28800초, 후보 9/이번 한정 9개다.
전역 8후보 정책과 다른 작업의 한도는 그대로다.

- 고정 run_id·계획 해시에 결합한 `CANDIDATE_ALLOWANCE.json`을 검증한다.
  다른 작업, 변경된 계획, 2개 추가 또는 시간 제한 확대는 거절한다.
- 자동 tick은 추가 허용을 스스로 생성하지 않는다. 사용자 요청에 따른 명시적
  등록만 가능하며 이미 발행한 후보에 다시 허용할 수 없다.
- 전역 정책·기존 원장 보존, 1회 예약, 9번째 후보의 안전 재개,
  시간/메모리/유휴 차단 및 변조 거절 테스트를 추가했다.
- 수정 전 새 테스트의 실패를 확인하고 수정 후 관련 **26 passed**를 확인했다.
- 최종 코드의 전체 회귀: **976 passed, 3 skipped, 31.18초**.
- 기존 Torch 격리 환경의 텐서/상태 테스트: **9 passed**.
  위 테스트 통과는 실제 훈련 또는 성능 개선을 의미하지 않는다.
- `compileall -q moa`, 평가 스크립트 컴파일, 기존 tick의 `sh -n`,
  `git diff --check`도 통과했다.

아직 발행되지 않은 계획의 구현 pin만 갱신했다. 이전 계획·상태·허용 기록과
변경 근거는 비공개 폴더에 별도로 보존했다. 데이터·학습 설정·기존 원장은 그대로다.

## 자동 실행과 보호 범위

기존 시간별 `com.moa.research`와 15분 앱 heartbeat `moa-r2`가 같은 컨트롤러,
장치 잠금과 단일 작업 ID를 사용했다. 새 cron·공개 포트는 만들지 않았다.
완료 후 앱 도구로 **`moa-r2`를 PAUSED**로 변경했다.
완료 상태에서 `advance`를 다시 호출해도 예약은 1건 그대로이며 추가 발행되지 않았다.
로컬 시간별 tick은 유지하되 이 고정 작업의 완료 상태만 반환한다.

NAS 운영 DB·원문·수집기·인증·운영 모델·사람 승인·자동 공개는 변경하지 않는다.
기존 모델과 blind는 보존한다. 유료 API, Muse/JEV, 모델 다운로드는 실행하지 않는다.
사용자가 맥북에 프롬프트나 파일을 전달할 필요는 없다.

상태 확인·중지·재개:

이 기록을 갱신했다. 코드 pin, 모든 새 체크포인트 파일 해시, 이전 원장 접두부와
전역 캠페인 상태의 불변을 재검증했다. 연구 프로세스와 장치 잠금은 모두 해제됐다.

## 남은 판단

실제 통신문 품질, 새 독립 시험, 사람 검수 성적 또는 직접 검사기 대비 추가 발견은
이번 실험에서 평가하지 않았다. 기존 blind를 열거나 사람 승인을 대신하지 않았다.
기존 운영 경로와 직접 검사·근거 가드를 유지한다.

다음 연구를 한다면 한 가지 변수는 **학습 단계도 정상/오류 두 범주로 맞추기**다.
이번 train은 통제 목적상 기존 3범주 구성을 유지했지만 평가는 두 선택지였고,
일정만 바꾼 뒤에도 두 범주의 점수 분리가 약했다. 근거 부족은 독립 근거 가드로
처리하는 비교가 다음 가설이다. 이는 제안일 뿐, 추가 후보·예산을 사용해 실행하지 않았다.
