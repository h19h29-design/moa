## 2. 실제 구현과 독립 근거

- 원문 SHA·계보·의미 양식·근접 문구를 연결해 제외하고, 변형 생성 전에 그룹 파티션을 고정했다.
- 기존 31파일·145문항·파생본·기존 평가/회귀 목록을 비공개 보호 목록으로 고정했다.
  보호 레코드 2,767개, 고유 source hash 831개이며 기존 원문/영수증 44파일의 불변을 재확인했다.
- 합성 원문의 별도 XML reader와 기존 MOA 파서·모바일 렌더러를 사용했다.
  외부 요청을 차단한 Chrome에서 **원문 20개와 변형 400건의 실제 DOM**을 관찰했다. 콘솔 오류 0.
- 실제 DOM의 날짜·시간·비용·선택 수·조건·각주·키-값 관계를 원문 사실과 각각 읽었다.
  결과에서 빠진 값을 원문으로 보충하지 않는다. 헤더·단위·각주·병합 정보도 관련 입력에 유지한다.
- 라벨은 독립 원문 사실과 기록된 연산으로 확정한다. 검사기/LAYA/JEV의 답을 복제하지 않는다.
  허용된 순서 변경과 관계 변경을 구분하고 no-op, 누락·중복·여분 행에 대한 회귀 검사를 추가했다.
- `moa.laya.fact-bundle.v1`과 같은 사실의 일반 텍스트 대조 `legacy_state`를 고정했다.
  gold·분할·변형 이름·파일명·판정은 모델 state/질문에 넣지 않는다.
- 독립 코드 검토에서 후속 tensor 감사가 이전 영수증만 믿고 checkpoint를 다시 확인하지 않던 문제를 발견했다.
  v4는 실제 checkpoint 전체를 tokenizer/config 사용 전·감사 후 재검증한다.
  formatter·generator·rubric도 변형 전 동결하고, 적격 원문이 0개이면 READY 생성을 거부한다.

자세한 입력·실행 경계는 [입력·인계 규격](R2_INPUT_AND_HANDOFF.md)에 기록했다.
자동 근접 문구/계보 검사는 모든 의미 유사 양식을 완벽히 찾는다는 보장이 아니다.

v3 incoming에는 superseded 표시를 추가했고, 맥북 소유 ledger·실행 코드·환경은 수정하지 않았다.
`REGRESSION_145_MAPPING.json`은 기존 145문항의 case·질문·입력 hash·gold 매핑을 고정하고,
맥북에 이미 있는 입력 파일 hash와 대조했다. 훈련·S0 선택·프롬프트 예시 사용은 금지했다.
888개 원문 부분 입력과 69개 보충 입력을 145문항 시험으로 잘못 취급하지 않는다.

**이 수신 영수증은 맥북 Codex의 훈련 시작/완료 영수증이 아니다.**
마지막 확인한 맥북 ledger는 `waiting_for_data`, train updates 0, 후보 예약 없음이다.
맥북 소유 실행기에 row.v2 guarded reader를 연결하고 S0→S1→R2-A를 실행하는 단계가 남았다.
600행 최소 조건을 맞추려고 자료를 복제하거나 dev/eval을 섞지 않도록 인계했다.

한도는 S1 32문항/40 updates/600초, R2-A 한 후보/2 epochs/400 updates/2700초,
총 440 updates/3300초다. 각 한도 중 먼저 도달하면 중지한다.
240행·micro1/accum8에서 2 epochs는 약 60 optimizer updates이며 400을 채우는 목표가 아니다.
R1에서 새 optimizer/scheduler·동결 encoder로 시작하고 저장 후 별도 재로딩 평가한다.
S0+최종 평가 총 2700초, 조각당 600초 제한도 전달했다.

blind는 맥북의 입력/설정·후보 hash 고정 영수증을 받은 뒤 **평가 소유 프로세스에만** 제공한다.
`source_complete=false`로 worker가 insufficient를 강제하는 값과 모델 원판정은 따로 집계한다.
