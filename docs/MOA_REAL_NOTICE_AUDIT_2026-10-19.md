# MOA 실제 원문 재검증·수정 결과 — 2026-10-19

## 결론

실제 원문을 다시 읽어 HWP/HWPX 파서와 신청서 구분, 모바일 표 표시 문제를 수정했다.
검사 대상 원문 문구의 화면 보존은 **1,327/1,329(99.85%)**, 원문 표는 **86개·1,825셀 대조 일치**였다.
실제 HTML에 기록된 오류를 넣은 고정 시험은 직접 검사·근거 기반 결합 모두 **145/145**였다.

이 수치는 **실제 통신문 전체의 독립 정답률 98%를 입증한 것은 아니다.**
문구 보존, 표 좌표, 명시적 오류 검출은 서로 다른 지표다. 전체 원문의 이미지·의미·파일 역할까지
독립적으로 확인한 사람 정답이 없으므로, 전체 변환 정확도와 실제 정상 문서 오탐률은 미측정이다.
LAYA R1 단독도 이번 시험에서 **79/145(54.5%)**로 98%가 아니다.

## 실제 수정 사항

- HWPX에서 본문과 표의 원래 순서를 보존했다. 서식 run마다 문장이 끊기거나 셀 문구가 본문에
  중복되고 표만 뒤로 이동하던 경로를 수정했다. 중첩 표의 셀 좌표를 바깥 셀 좌표로 읽는 문제도 막았다.
- HWP 제어문자 뒤의 실제 한글이 사라지는 결함을 고쳤다. 실제 신청서의 `참관신청 과목`이
  `참관`으로 잘리던 경우를 재현했다. 제어문자의 닫힘 표식, UTF-16 단위 길이, 공백 제어문자를 처리한다.
  [한컴 HWP 5.0 형식 명세](https://cdn.hancom.com/link/docs/%ED%95%9C%EA%B8%80%EB%AC%B8%EC%84%9C%ED%8C%8C%EC%9D%BC%ED%98%95%EC%8B%9D_5.0_revision1.3.pdf)의 제어문자 구분을 확인했다.
- 신청서 제목과 두 종류의 기입란·빈 셀이 명확한 표를 원본 서식으로 구분했다.
  서식 제목 아래에 인쇄된 회신 기한·제출 지시는 모바일 안내에 남겼다.
  불명확한 경계는 확인 완료로 바꾸지 않았다.
- PDF 텍스트에 미해석 제어문자나 대체문자가 있으면 완전 추출로 처리하지 않는다.
  글자 복원에 성공한 것으로 가장하거나 임의 OCR을 수행하지 않는다.
- 병합 표의 열이 휴대폰 너비에 과도하게 눌리지 않도록 최소 폭과 기존 가로 스크롤을 사용했다.
  실제 8열 표는 640px로 유지되고 333px 영역 안에서 스크롤되며 페이지 전체 넘침은 없었다.
- 큰 첨부 ZIP 검증이 Node/Python 표준입력 전송에서 멈추던 문제를 수정했다.
  비공개 임시 파일·15초 제한을 사용하고 작업 전용 임시 파일만 정리한다. 원본 ZIP은 변경하지 않는다.

최종 파서: `moa-local-v8-native-controls`, 변환기: `moa-notice-v7-readable-tables`.
직접 검사기는 기존 `moa-content-gate-v3-evidence`다. 원문·추출·변환·사람 승인 버전은 구분한다.

- 새 유료 외부 AI·Muse/JEV 호출·훈련·자동 공개·사람 대신 승인 모두 **0**.
  Muse `default.execratings` 빈 인자 오류는 미해결이며 작업과 분리했다.
- 지원 범위는 검증한 HWP5/HWPX와 읽을 수 있는 텍스트 PDF다.
  스캔·이미지 OCR, 암호화 HWP, 잘못된 PDF 문자 매핑, 불명확한 구간, 1024토큰을 넘는 완전한 행은
  성공으로 표시하지 않는다. 이번 PDF 안내 표본은 1개뿐이다.

남은 핵심은 원문 전체·이미지·안내/첨부 경계에 대한 독립 정답을 확보하는 것이다.
이번 개선은 실제 누락·구조·표시 결함의 수정과 직접 검증 강화이며, 모델이 재학습돼 98%가 된 것이 아니다.
추가 재학습이나 반복 추론으로 점수를 맞추지 않고, 다른 원문·양식 그룹의 독립 평가를 다음 비교 변수로 둔다.
