# 여러 묶음 영수증 검색 결과 CSV — 24단계, 2026-10-29

## 사용 흐름

**내 다운로드 영수증 모아보기**에서 묶음 이름·기록일·현재 보관 상태를 검색한 뒤
**검색 결과 전체 CSV 다운로드**를 누른다. 현재 페이지뿐 아니라 같은 조건에 맞는
모든 묶음·모든 페이지의 영수증을 한 파일에 담는다. 검색 결과가 없으면 열 제목만 내보낸다.

화면을 연 시점을 고정한 목록이 아니라 **다운로드 요청 시점**에 동일 조건을 다시 검색한 결과다.
요청 내부의 학교/계정 확인·영수증·현재 보관 상태는 하나의 SQLite 읽기 스냅샷을 사용한다.
다운로드 사이에 새 영수증이나 보관/복원이 생기면 다음 파일에는 반영될 수 있다.

최대 5,000건은 여러 묶음을 합친 검색 결과 전체의 한도다. 5,001건 이상이면 파일을 내보내지 않고
이름·기간·보관 상태로 범위를 줄이도록 안내한다. 검색 결과로 돌아가는 링크는 조건을 유지한다.
페이지 단위로 일부만 담거나 초과분을 조용히 잘라내지 않는다.

원본·수신/변환 버전·검수 이력·고정 목록·보관/복원 이력·다운로드 영수증을 변경하지 않는다.
CSV를 내려받아도 새 영수증을 추가하지 않는다. 보관되거나 문서 검수가 다시 열린 묶음의 과거 영수증도
내보낼 수 있지만, 실제 문서 ZIP의 버전 변경 차단은 그대로 유지한다.

## HTTP·CSV 계약

`GET /confirmed-export/receipts.csv`를 추가한다.

- 선택 입력: `q`, `from`, `to`, `state`. 기존 모아보기와 같은 검색/권한 함수를 공유한다.
  이름은 최대 120자의 문자 그대로 부분 검색(ASCII 대소문자 무시), 기간은 한국 시간의 영수증 기록일 양 끝 날짜 포함,
  상태는 `all`/`active`/`archived`이며 기본은 `all`이다.
- `page`, `id`, `school`, `subject` 등 알 수 없는 입력이나 중복 필드·잘못된 날짜/상태·과도한 길이는 400이다.
  조회 문자열 한도 4,096자를 유지한다. POST는 CSV를 내보내지 않는다.
- 열은 묶음 ID·묶음 이름·다운로드 회차·기록 시각(한국 시간)·문서 수·ZIP 바이트·ZIP SHA-256·묶음 현재 상태다.
  상태는 `사용 중`/`보관함`으로 표시한다. 계정·학교 식별자·원문·첨부·검수 본문을 담지 않는다.
- 정렬은 화면과 동일한 기록 시각 → 묶음 ID → 회차 내림차순이다. 같은 시각에도 순서를 유지한다.
- UTF-8 BOM·CRLF·CSV 표준 인용을 사용한다. 기존 CSV 수식 방지 함수를 재사용하여
  수식으로 해석될 수 있는 묶음 이름/ID 등에는 내보내는 값에만 작은따옴표를 붙인다. 저장된 값은 변경하지 않는다.
- 파일명은 `confirmed-export-receipts-overview.csv`, Content-Type은 `text/csv; charset=utf-8`이다.
  attachment·`private, no-store`·`nosniff`·기존 CSP를 유지한다.
- 5,000건까지 성공, 5,001건부터 400과 HTML 안내를 반환한다. 최대 한도+1건만 가져와 초과를 판별한다.
  필요한 기존 테이블이 없으면 409와 설치 필요 안내를 반환하며, 빈 CSV 성공으로 처리하지 않는다.

현재 학교 소속과 계정을 읽기 스냅샷 안에서 확인한다. 다른 학교·같은 학교의 다른 담당자 기록은 포함하지 않는다.
reader로 바뀐 소유자는 자기 과거 영수증을 읽을 수 있다. 소속 해제·학교 비활성·미로그인은 차단한다.
새 DB 테이블·마이그레이션·인덱스·트리거 변경이 없으며 기존 v9을 읽기만 한다.
CSV는 요청 메모리에서 반환하고 서버에 별도 CSV 파일을 저장하지 않는다. 문서 분석·변환·ZIP 생성도 호출하지 않는다.
