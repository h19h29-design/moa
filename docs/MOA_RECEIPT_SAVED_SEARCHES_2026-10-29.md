# 영수증 검색 조건 저장 — 25단계, 2026-10-29

## 사용 흐름

**내 다운로드 영수증 모아보기**에서 묶음 이름·기록일·묶음 현재 상태를 검색하고,
검색 조건 이름을 입력해 **현재 검색 조건 저장**을 누른다. 검색 버튼으로 적용한 조건을
저장하므로 검색란을 바꿨다면 먼저 검색한다. 현재 페이지 번호는 저장하지 않는다.

**저장한 검색 조건 불러오기**에서 개인 목록을 열 수 있다. 재로그인 후 **조건 불러오기**를
누르면 저장한 조건의 첫 페이지가 열린다. 이어서 **검색 결과 전체 CSV 다운로드**를 누르거나,
저장한 조건 목록의 **이 조건의 전체 CSV 다운로드**로 바로 받을 수 있다.

저장하는 것은 이름·기간·보관 상태다. 영수증 결과나 CSV 바이트를 고정하지 않는다.
불러오기·다운로드 시점의 현재 영수증과 묶음 상태로 다시 검색한다. 새 영수증·보관/복원은
다음 조회에 반영된다. 동일 이름의 새 조건도 별도 항목으로 보존하며 기존 조건을 덮어쓰지 않는다.
이번 범위에는 조건 수정·삭제·공유·예약 다운로드가 없다.

전체 CSV는 기존 24단계 경로와 검증을 그대로 사용한다. 모든 묶음·모든 페이지를 합쳐
최대 5,000건, 5,001건부터 일부 파일도 내보내지 않고 조건 축소를 안내한다.
기간은 한국 시간의 영수증 기록일 양 끝 날짜를 포함하며, 보관 상태는 묶음의 현재 상태다.
빈 결과는 열 제목만 내보낸다. UTF-8 BOM·CSV 인용·수식 방지·비공개 응답 헤더를 유지한다.

## DB·권한·HTTP 계약

명시적인 추가형 학교 DB 마이그레이션 **v10**은 다음만 추가한다.

- `school_receipt_searches`: 24자 ID, 학교·계정, 이름(1~120자), 묶음 이름 검색(최대 120자),
  시작일·종료일, `all`/`active`/`archived`, 조건 저장 시각.
- 학교·계정·저장 시각·ID 순서의 목록 인덱스, 기존 학교 소속에 대한 FK.
- 저장한 조건의 UPDATE/DELETE를 막는 트리거. 영수증·검수·원본 테이블에는 DDL/DML을 적용하지 않는다.

기존 v9 DB를 마이그레이션하기 전에 기존 `Store.backup`으로 WAL 일관 백업을 만들고
하나의 트랜잭션에서 스키마와 마이그레이션 표식을 추가한다. 실패 시 추가 스키마도 롤백한다.
기존 `PRAGMA user_version`과 모든 기존 데이터 행은 보존한다. 이미 v10이면 아무것도 하지 않으며
알 수 없는 버전·중간 버전 누락은 기존처럼 거절한다. 이번에는 외장 SSD의 격리 합성 DB에서만 실행했다.

Store 열기·HTTP 조회·저장 요청은 자동 마이그레이션하지 않는다. v10 미설치 시 설치 필요 안내를 보이며,
조건 저장/불러오기는 409다. 기존 v9 영수증 검색과 CSV는 계속 사용할 수 있다.

| 요청 | 동작 |
|---|---|
| `GET /confirmed-export/receipt-searches` | 내 조건 목록. 선택 `page`, 페이지당 20개·마지막 페이지 보정 |
| `GET /confirmed-export/receipt-searches/open?id=...` | 소유자·현재 소속 확인 후 저장 조건으로 기존 검색 화면 이동 |
| `POST /confirmed-export/receipt-searches/save` | `csrf`, `id`, `name`, `q`, `from`, `to`, `state`만 받아 조건 저장 |
| 기존 `GET /confirmed-export/receipts.csv` | 저장 조건을 포함한 기존 검색 조건으로 전체 CSV 다운로드 |

저장에는 현재 쓰기 역할과 CSRF·Origin 검사가 필요하다. 요청 본문은 최대 8,192바이트이며
알 수 없는 필드·중복 필드·잘못된 날짜·역전 기간·상태·ID·과도한 길이는 차단한다.
서버가 생성한 폼 ID의 동일 내용 재전송은 중복 저장하지 않는다. 같은 ID로 내용을 바꾸면 409,
다른 소유자의 ID는 404이며 기존 조건을 노출하거나 수정하지 않는다. 동시 재전송도 한 건만 커밋한다.

학교와 계정은 로그인 세션에서만 결정한다. 다른 학교·동일 학교의 다른 담당자는 항목을 열 수 없다.
reader로 바뀐 소유자는 자기 기존 조건을 읽고 CSV를 받을 수 있으나 새 조건을 저장할 수 없다.
미로그인·소속 해제·학교 비활성은 차단한다. 목록/불러오기/CSV는 읽기 전용이고
CSV 다운로드 자체로 새 영수증을 기록하지 않는다. 문서 원본·검수 본문·ZIP 생성도 호출하지 않는다.
