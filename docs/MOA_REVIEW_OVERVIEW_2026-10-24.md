# 학교별 검수 현황·검색/필터 — 7단계, 2026-10-24

## 담당자 흐름

학교 전용 로그인 → 첫 화면의 **학교별 검수 현황** → 제목 검색 / 검수 상태 선택 →
검색 결과 → 수신본·원본 / 검수 열기 / 검수 이력 / 검수 HTML.

- 로그인한 학교의 최신 수신본만 목록에 한 번 표시한다. 학교 전체 건수와
  **미검수 / 수정 중 / 확인 완료 / 변환 오류** 건수를 제공한다.
- 전체 집계는 검색 조건과 무관하다. 검색 결과 건수·현재/전체 페이지는 필터 결과 기준이다.
- 제목 일부를 문자 그대로 검색한다. `%`, `_`, `\`, 따옴표는 SQL 명령·와일드카드로 해석하지 않는다.
  본문·개인정보·검수 사유 전체 검색은 이번 범위가 아니다.
- 최신 수신순(`updated_at DESC,id`)으로 페이지당 최대 20건. 이전/다음 이동은 검색어와 상태를 보존하고,
  새 검색은 첫 페이지로 시작한다. 범위를 넘는 정상 페이지 번호는 마지막 페이지로 보정한다.
- 각 항목은 수신/변환/검수 순번, 수신 시각, 출처, 검수 담당자·시각, 변환 전/중/완료/오류를 표시한다.
- 기존 업로드·역할·변환·수신 출처·작업 재시도 화면은 유지한다. 홈페이지 수집·공개를 켜지 않는다.

## 최신 상태·이력 계약

| 상태 | 판단 기준 |
|---|---|
| 미검수 | 현재 수신본·변환 버전의 검수 기록 없음. 변환 전/중도 포함하되 변환 상태를 별도 표시 |
| 수정 중 | 현재 변환의 마지막 검수 이벤트가 `draft`. 과거 검수본 복원도 새 draft로 표시 |
| 확인 완료 | 현재 변환의 마지막 검수 이벤트가 `confirmed`이고 재변환 진행/실패 상태가 아님 |
| 변환 오류 | 현재 수신본의 변환 상태가 `conversion_failed`; 과거 확인 완료가 있어도 오류로 표시 |

정정 수신본·재변환은 과거의 확인을 승계하지 않는다. 재변환 진행/실패 중 남아 있는
기존 검수·HTML·이력 링크는 **이전 변환본 기준**이라고 표시한다.
확인 완료는 저장된 담당자 검수 상태이지, 공개 승인·모델 점수·새 원본 무결성 검사의 결과가 아니다.

- **검수 열기**: 수신본/변환 ID를 고정해 해당 변환의 최신 검수 화면을 연다. 기존 동시 수정 충돌 검사를 재사용한다.
- **검수 이력**: 수신본/변환 ID를 고정한다. 기존 이력·비교·복원 흐름을 그대로 사용한다.
- **검수 HTML**: 수신본/변환/검수 이벤트 3개 ID를 고정한 기존 미리보기로 이동한다.
  이후 다른 수정이 생겨도 그 시점의 HTML/ZIP을 열 수 있다.
- 아직 구조 분석이 없거나 크기 제한을 넘는 변환은 바로 검수 링크를 제시하지 않고 수신본에서 상태를 확인하도록 안내한다.

## 읽기 전용 DB·보안 계약

새 테이블·인덱스·스키마 마이그레이션은 없다. 기존 학교 schema v1/v2와
`school_service_posts/versions`, `mobile_notices/revisions`, `school_structure_reviews`를 조회한다.
v1에서는 마이그레이션 필요 안내만 하고 DB를 자동 변경하지 않는다.

- `GET /`: 허용 query는 `q`, `status`, `page` 각각 하나씩. 중복·미지원 필드·잘못된 UTF-8·제어 문자 거부.
- query 문자열 최대 4,096자, 검색어 최대 200자, 상태 allowlist, 페이지 1–1,000,000.
- 학교는 서버 세션에서만 얻는다. `school`/`subject` query로 변경할 수 없다.
  reader 조회 허용, 탈퇴/권한 회수/학교 중지 즉시 재검사, 다른 학교 건수·제목·링크 제외.
- SQL 값 바인딩, HTML escape, 기존 인증·`no-store`·CSP 재사용.
  검색어·문서 제목을 URL 접근 로그에 추가하지 않는다(기존 HTTP access logging 비활성 유지).
- 하나의 read savepoint에서 권한·전체 집계·필터 건수·페이지를 조회한다. 별도 worker connection에서
  수신이 추가되어도 한 응답의 집계/목록은 같은 snapshot이며, 호출자의 기존 transaction을 commit하지 않는다.
- 집계/필터는 metadata만 읽고 review `overlay`/`changes`를 전부 읽지 않는다.
  표시할 최대 20건만 기존 변환 payload의 구조 유무를 확인하며, 8MiB 초과/비정상 JSON은 해석하지 않는다.
- 조회로 원본 객체·자동 분석·검수 이벤트·학습·큐·공개 상태를 생성/수정하지 않는다.
