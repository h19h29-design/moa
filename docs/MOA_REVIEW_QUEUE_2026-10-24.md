# 학교별 연속 검수 — 8단계, 2026-10-24

## 담당자 흐름

학교 로그인 → 현황에서 제목/검수 상태 검색 → **이 페이지 연속 검수 시작** →
현재 문서 수정·저장·확인 → 이전/다음 문서 → 검색 목록으로 돌아가기.

- 시작 시 현재 검색 페이지의 검수 가능한 문서만 최대 20건 선택한다.
  변환 전/진행/실패, 구조 없는 문서는 제외한다. 빈 목록에서는 이유와 목록 복귀 링크를 제공한다.
- 수신본 ID·변환 ID·순서를 고정한다. 첫 문서를 확인해 `미검수` 필터에서 빠져도
  다음 문서를 건너뛰지 않는다. 검수 이벤트는 고정하지 않고 해당 변환의 최신 검수를 표시한다.
- 각 문서의 수정·확인·확인 취소는 기존 저장 버튼으로 개별 수행한다.
  자동 저장·일괄 확인·자동 승인·공개는 하지 않는다. 저장 후에도 같은 문서에 머문다.
- 이전/다음 이동, 구역/관계 쪽 넘김, 현재 문서 다시 열기를 제공한다.
  목록 복귀 시 제목·상태·페이지를 유지한다. 목록 끝에서는 검색 결과의 다음 페이지에서 새로 시작한다.
- 수정 중 이동 시 입력을 버릴지 묻는다. 다른 구역에 저장하지 않은 입력이 있으면
  한 항목을 저장할 때도 경고한다. JavaScript가 꺼져 있으면 수동 저장 안내만 제공한다.
  브라우저 종료·세션 만료에 대비한 자동 초안 복구 기능은 아니다.
- 기존 자동 분석·이력·비교·HTML 링크는 수신/변환/검수 시점을 고정하는 기존 계약을 유지한다.

## 세션·DB·보안 계약

새 테이블·마이그레이션·지속 작업 큐는 없다. 기존 학교 전용 로그인 메모리에
문서 ID·변환 ID·제목과 검색 조건만 저장한다. 문서 본문·수정 입력은 URL이나 목록에 넣지 않는다.

| 경로 | 동작 |
|---|---|
| `GET /review-queue/start?q=…&status=…&page=…` | 기존 현황 조회를 재사용하고 로그인 메모리에 현재 페이지 목록 생성. DB 쓰기 없음 |
| `GET /review-queue?queue=…&item=…` | 해당 로그인 목록의 고정 수신/변환 검수 화면 조회. DB 쓰기 없음 |
| `GET /static/school-queue.js` | 인증 후 입력 유실 경고 스크립트 제공. 문서 전송/저장 없음 |
| `POST /structure-review` | 기존 CSRF·현재 권한·변환/hash·직전 검수 이벤트 검사를 그대로 재사용하고 성공 시 같은 목록 항목으로 복귀 |

- 한 로그인에 최대 3개 목록만 유지한다. 네 번째 시작 시 가장 오래된 목록을 제거한다.
  목록은 기존 로그인 만료(8시간)·로그아웃·서버 재시작 시 사용할 수 없다. 영구 업무 배정이 아니다.
- 무작위 목록 키만으로 권한을 얻지 못한다. 로그인 세션·학교·담당자에 결합하고 매번 소속을 다시 검사한다.
  같은 담당자의 별도 로그인에도 목록을 공유하지 않는다. reader는 읽기만 가능하다.
- 시작 query는 기존 제목/상태/페이지 allowlist를 사용한다. 항목 query는 최대 4,096자·4개 필드,
  목록 키/항목 번호/구역·관계 페이지 외 필드·중복·잘못된 UTF-8을 거부한다.
- 저장의 목록 키/항목 번호와 수신본/변환 ID가 다르면 저장 전에 거부한다.
  중복 저장·다른 담당자 수정은 기존 부모 이벤트 충돌 검사로 409 처리한다.
- 정정 수신본·재변환이 생겨도 새 문서로 몰래 바꾸지 않는다. 고정된 이전 버전은 읽기 전용이며
  저장은 거부한다. 구조가 손상되면 안전한 오류와 이전/다음/목록 링크를 제공하고 다른 변환으로 대체하지 않는다.
- **보완한 경계:** 목록 시작 후 재변환이 실패한 경우도 읽기 전용·저장 409로 처리한다.
  기존 직접 검수 경로에도 동일하게 적용한다. 실패 전에 남은 변환본을 현재 확인 완료로 만들지 않는다.
- SQL 값 바인딩·텍스트 HTML escape·기존 no-store/CSP/SameSite/CSRF를 유지한다.
  외부 스크립트·유료 API·모델은 없다. 제목/입력/목록 키를 접근 로그에 추가하지 않는다.
- 원본 SHA 객체·자동 변환 payload·기존 검수 이벤트는 덮어쓰지 않는다.
  명시적 저장만 기존 추가형 `school_structure_reviews`에 새 이벤트를 남긴다.

## 실제 검증

신규 HTTP 테스트 **20개**를 추가했다. 먼저 누락된 연속 검수 경로의 실패를 확인했고,
재변환 실패 후 확인을 막는 추가 회귀 테스트도 수정 전 실패를 확인했다.

- 최종 전체 회귀: **1,494 통과 / 16 skip / 실패 0**, 130.44초 (`full-final.xml`).
  skip은 기존 선택적 모델/Torch·맥북 전용 검사 등이며 이를 해제하려고 모델을 설치/호출하지 않았다.
- 학교 A/B·동일 담당자 별도 로그인·reader·권한 회수·로그아웃·목록 3개 제한,
  20/1건 페이지 경계·비준비 문서 제외·상태 필터 변경 후 이동·목록 복귀를 검증했다.
- 위조 수신/변환/목록·중복 필드·교차 origin·CSRF·저장 재전송·정정/재변환/변환 실패·
  손상된 구조·제목 XSS·구역 쪽 넘김을 검사했다. 조회/거부 전후 DB dump가 동일하다.
- HWP(기취득 비공개 fixture)·합성 HWPX·DOCX·텍스트 PDF 모두 실제 parser `extracted`.
  업로드 → 역할 → 변환/HTML·원본 ZIP → 검수 → 비교/복원 → 현황 → 연속 검수까지 HTTP 200.
  수신/변환 ID 고정 및 원본·추출 캐시 bytes/mtime·기존 이력 보존 검사를 통과했다.
- `compileall -q moa`, `node --check moa/school_queue_ui.js`,
  `sh -n scripts/install-nas.sh`(구문 검사만), `git diff --check` 통과.

### 브라우저와 자체 검토

Browser plugin/skill이 없어 기존 Playwright와 설치된 Chrome을 사용했다.
합성 학교 loopback 서버에서 1280×900 데스크톱 및 390×844 모바일로 다음을 실제 조작했다.

- 제목+미검수 필터 4건 중 준비된 3건만 연속 검수 시작, 다른 학교 미노출.
- 수정 입력 후 다음 이동 취소 및 다른 입력란이 변경된 상태의 확인 제출 취소.
- 본문 수정 저장 → 같은 항목 유지 → 확인 완료 → 다음/이전 → 마지막 문서 → 조건 유지 목록 복귀.
- 확인 후에도 목록의 2·3번째 문서를 누락하지 않으며, 돌아온 미검수 목록은 3건으로 갱신.
- 모바일 긴 변환 ID의 가로 넘침을 발견해 검수 영역의 줄바꿈/입력 폭을 보완했다.
  최종 모바일 가로 넘침 없음, 화면 이미지와 브라우저 실행 결과를 저장했다.
- 앱 runtime 오류 없음. 기존 미구현 `/favicon.ico`의 401/404 두 건만 별도로 설명했다.

브라우저 종료 후 원본/추출 SHA·mtime, 변환 payload, 이전 검수 이벤트,
검수 테이블 외 DB 내용이 모두 동일했다. 합성 본문 저장·확인의 새 이벤트 2개만 추가됐다.
이 작업이 실행한 서버·전용 브라우저만 종료했다. 다른 앱·서비스는 종료하지 않았다.
보안/입력 경계와 화면 검증 스킬을 적용한 자체 diff 검토이며, 별도 모델/에이전트 검토나 운영 검증은 아니다.
