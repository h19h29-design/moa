# 연속 검수 목록 저장·이어하기 — 9단계, 2026-10-24

## 담당자 흐름

학교 로그인 → 현황에서 검색·필터 → **이 페이지 연속 검수 시작** →
목록 이름 입력 → **목록 저장·이어서 검수** → 문서별 수정·저장·확인 →
**이전/다음 문서·위치 저장** → 종료 또는 로그아웃.

나중에 같은 담당자 계정으로 로그인 → 상단 **저장한 검수 목록** →
원하는 목록의 **이어서 검수**로 마지막 저장 위치를 연다.
서버 재시작으로 로그인 메모리가 사라져도 SQLite에 저장한 목록은 남는다.

- 시작한 검색 페이지의 최대 20건, 수신 ID·변환 ID·제목·순서·검색 조건을 고정한다.
  현재 변환 완료·구조 분석 가능 문서만 고르는 기존 8단계 계약을 재사용한다.
  이후 문서가 확인 완료되어 검색 필터에서 빠져도 저장한 순서는 바뀌지 않는다.
- 목록 이름은 1–120자이며 목록은 해당 학교·담당자 계정에만 보인다.
  같은 계정의 새 로그인에서는 이어갈 수 있지만 다른 담당자·학교는 볼 수 없다.
- 목록 저장은 문서의 **입력 중인 수정 내용**을 저장하지 않는다.
  수정·확인·확인 취소는 기존 문서별 저장 버튼으로 수행하고, 기존 추가형 이력에 남긴다.
  자동 초안 저장·일괄 확인·완료 상태 자동 변경·공개·업무 배정 기능은 아니다.
- 이전/다음 버튼은 명시적 POST로 재개 위치만 저장한다.
  화면의 `2 / 3`은 두 건의 검수 완료가 아니라 두 번째 문서 위치다.
  검수 상태는 해당 수신/변환의 최신 검수 이벤트에서 계속 읽는다.
- 조회 GET, 구역/관계 쪽 넘김, 링크 미리보기·새로고침은 위치를 변경하지 않는다.
  직접 항목 링크로 다른 위치를 열면 현재 저장 위치도 함께 표시하며
  **여기부터 이어하기·위치 저장**을 눌러 명시적으로 변경할 수 있다.
- 미저장 입력이 있는 목록 저장·위치 이동은 JavaScript 확인 창을 거친다.
  JavaScript가 꺼지면 저장 후 이동하라는 안내를 제공하며 초안을 자동 복구하지 않는다.
- 같은 목록을 중복 저장해도 목록을 복제하거나 이름·이후 재개 위치를 초기화하지 않는다.
  세션의 최대 3개 임시 목록 제한은 저장된 목록을 지우지 않는다.
  저장 목록은 페이지당 20개씩 조회하며 이 단계에서는 삭제·자동 만료를 제공하지 않는다.

## 추가형 DB와 명시적 마이그레이션

`school_service.migrate`의 명시적 v3 마이그레이션에 두 테이블을 추가했다.
실제 적용·복원 검증은 **외장 SSD의 격리 테스트 DB에서만** 수행했다.
NAS 운영 DB에는 접속하거나 적용하지 않았다.

| 테이블 | 계약 |
|---|---|
| `school_review_lists` | 무작위 24자 ID, 학교·담당자, 이름·검색 조건, 항목 수, 재개 위치, 충돌 버전, 생성/위치 저장 시각 |
| `school_review_list_items` | 목록별 1–20 순번, 학교, 고정 수신/변환 ID와 제목. 본문·원본 bytes·입력 초안은 저장하지 않음 |

- 기존 v1/v2에서 추가 적용하며 `PRAGMA user_version`은 그대로다.
  DDL 전에 기존 `Store.backup`으로 WAL-consistent SQLite 백업을 `db/backups`에 생성한다.
  재호출은 무변경이며 알 수 없는 버전은 중단한다.
- FK와 INSERT 범위 trigger로 같은 학교의 실제 수신본·그 변환본에만 결합한다.
  항목·순서와 목록 소유자·이름·검색 조건은 UPDATE/DELETE trigger로 고정한다.
  위치·충돌 버전·최근 시각만 명시적 이동 트랜잭션에서 변경한다.
- `BEGIN IMMEDIATE` 안에서 현재 권한과 기대 버전을 확인한다.
  오래된 탭이나 중복 이동 POST는 409이며 최신 위치를 덮어쓰지 않는다.
- 문서·목록 조회나 학교 서버 시작은 마이그레이션을 하지 않는다.
  v2 DB는 기존 세션 연속 검수를 계속 제공하고 목록 저장에는 마이그레이션 필요를 안내한다.
  NAS 적용은 별도 승인·운영 백업/검증이 필요한 후속 작업이다.

## 경로와 보호 경계

| 경로 | 동작 |
|---|---|
| `POST /review-queue/save` | 로그인 메모리의 고정 목록을 현재 위치와 함께 저장. 클라이언트가 보낸 문서 배열은 받지 않음 |
| `GET /review-saved`, `GET /review-saved/lists?page=…` | 내 저장 목록 메타데이터만 20개 단위 조회 |
| `GET /review-saved?id=…[&item=…]` | 고정 문서 조회. item 생략 시 저장 위치. DB 쓰기 없음 |
| `POST /review-saved/move` | CSRF·현재 쓰기 권한·학교/담당자·기대 버전 확인 후 위치만 저장 |
| `POST /structure-review` | 저장 목록 ID/순번과 수신/변환 ID 일치 확인 후 기존 개별 검수 저장·충돌 검사 재사용 |

- 모든 경로에 기존 학교 인증·현재 소속 재확인·권한·no-store·CSP를 유지한다.
  reader로 권한이 낮아지면 자기 저장 목록도 조회만 가능하며 새 목록/위치는 저장할 수 없다.
  소속 비활성화·학교 중지는 읽기와 쓰기를 모두 차단한다.
- 쿼리 4,096자·경로별 필드 allowlist·중복 거부·정수 범위·UTF-8 엄격 검사,
  POST 본문 크기 제한과 기존 Origin/CSRF 보호를 적용한다.
  SQL 값 바인딩과 HTML escape를 사용한다. 접근 로그에 목록/문서/입력을 새로 남기지 않는다.
- 정정본·재변환·변환 실패가 생겨도 고정 대상을 최신본으로 몰래 바꾸지 않는다.
  기존 버전은 읽기 전용·저장 거부다. 구조가 손상되어도 안전한 오류와 목록 이동을 유지한다.
- 원본 SHA 객체·추출 캐시·자동 변환 payload·기존 검수 이력을 덮어쓰지 않는다.
  검수 저장은 기존 감사 테이블에 새 이벤트만 추가하고 목록 저장은 별도 두 테이블만 쓴다.
- 실서비스 홈페이지 수집·연구용 수집/백필·공개 설정·운영 인증과 배포는 변경하지 않는다.
  맥북 학습·모델 추론·유료/외부 모델·추가 에이전트도 호출하지 않았다.

  기존 선택적 검사 skip을 해제하려고 모델/맥북 작업이나 의존성 설치를 하지 않았다.

  `sh -n scripts/install-nas.sh`(구문 검사만), `git diff --check` 통과.
