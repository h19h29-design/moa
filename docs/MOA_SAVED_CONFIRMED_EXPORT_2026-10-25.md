# 확인 완료본 묶음 목록 저장·재로그인 후 다운로드 — 18단계, 2026-10-25

## 담당자 흐름

1. 학교 현황에서 **확인 완료본 선택·묶음 다운로드**를 열고 최대 10건을 준비한다.
2. 문서·확인 시점·남은 경고를 대조한 뒤 이름을 입력하고 **목록 저장·나중에 다운로드**를 누른다.
3. 로그아웃·재로그인 후 학교 현황의 **저장한 묶음·이어서 다운로드**에서 내 목록을 연다.
4. 고정한 문서 순서와 확인 버전을 재검사한 결과를 확인하고, 확인란을 직접 선택해 ZIP을 받는다.
5. 수신·변환·검수 버전이나 원본 무결성이 달라지면 묶음 전체를 차단한다.
   저장 목록은 그대로 남으며 최신 확인본을 새 목록으로 준비할 수 있다.

서버 재시작 후에도 내 계정으로 목록을 열 수 있다. 재개 시 고정 목록을 재검사해 ZIP 전체를 다시 생성한다.
저장은 다운로드·확인 완료 처리·공개 승인을 자동 실행하지 않는다. 경고와 미확정 범위도 보존한다.
JavaScript가 꺼져 있어도 저장·재로그인·재개·다운로드가 가능하다.

## 권한·버전·HTTP 계약

| 경로 | 계약 |
|---|---|
| `POST /confirmed-export/save` | 현재 세션의 준비 목록과 이름을 검증하고 담당자 전용 목록을 원자적으로 저장 |
| `GET /confirmed-export/saved?page=…` | 내 학교·내 계정의 저장 목록을 20개씩 조회 |
| `GET /confirmed-export/saved/preview?id=…` | 저장한 버전·전체 스냅샷 해시를 재검사하고 다운로드 전 확인 화면 표시 |
| `POST /confirmed-export/saved/download` | 현재 권한·명시적 확인·버전·원본 무결성을 재검사한 뒤 ZIP 전체 반환 |

- 학교와 담당자는 인증 세션에서 결정한다. 같은 계정의 새 로그인은 저장 목록에 접근할 수 있다.
  다른 담당자·다른 학교·로그인 없는 사용자는 접근할 수 없다. 추측한 목록 ID로도 접근할 수 없다.
- 목록 저장은 기존 쓰기 권한이 있는 담당자만 가능하다. reader는 기존 임시 묶음 다운로드를 계속 이용한다.
  목록 소유자가 reader로 바뀐 경우에는 기존 원본/HTML 열람 권한 안에서 본인의 저장 목록을 내려받을 수 있다.
  소속 해제·학교 비활성 상태는 매 요청의 인증 검사에서 차단한다.
- 목록은 문서 순서·수신 ID·변환 ID·확인 이벤트 ID·전체 스냅샷 SHA256·당시 제목을 고정한다.
  본문·원본·모델·ZIP 사본을 DB에 중복 저장하지 않는다.
- 저장은 `BEGIN IMMEDIATE` 안에서 현재 확인 버전을 재검사한 뒤 목록과 항목을 함께 추가한다.
  같은 준비 ID·이름·고정 내용의 재전송/동시 저장은 한 번만 저장된다.
  같은 ID를 다른 이름·순서로 덮어쓰거나 다른 담당자가 재사용할 수 없다.
- 정정본·재변환·검수 수정·확인 취소·새 확인 이벤트·스냅샷 변경은 409로 차단한다.
  원본 누락·변조·간접 경로·저장 항목 손상도 다운로드를 차단한다.
  새 버전으로 자동 대체하거나 일부 문서만 제외한 ZIP을 반환하지 않는다.
- 목록 열기·재로그인·다운로드는 저장 행·원본·검수 이력을 쓰지 않는다.
  한 요청의 ZIP은 기존 17단계의 일관된 SQLite 읽기 시점에서 생성하며, 다음 요청에서 현재 버전을 다시 검사한다.
- 목록당 최대 10건, 원본 합계 64MiB, HTML·근거·루트 목록을 포함한 ZIP 내용 합계 96MiB를 유지한다.
  단건 파일 수/크기와 SHA 검사는 기존 단건 묶음 코드를 재사용한다. 중간 ZIP을 디스크에 쓰지 않는다.
- 두 새 POST는 16,384바이트, GET query는 4,096자로 제한한다.
  CSRF·Origin·중복/추가/빈 필드·잘못된 UTF-8·ID·이름·명시적 확인을 검증한다.
  이름과 제목은 HTML escape하며 기존 CSP·no-store를 유지한다. 확인란은 열 때마다 비워 둔다.
- 저장하지 않은 기존 준비 목록은 여전히 로그인당 최근 4개만 유지한다.
  이를 지우거나 세션이 끝나도 저장한 목록은 영향을 받지 않는다.

## 추가형 DB 계약

학교 전용 schema v7을 기존 명시적 `school_service.migrate`에 추가했다.

| 추가 대상 | 내용 |
|---|---|
| `school_confirmed_export_lists` | 24자 ID, 학교/담당자 FK, 이름, 항목 수, 저장 시각; 담당자별 목록 index |
| `school_confirmed_export_items` | 고정 순서, 수신/변환/확인 이벤트 FK, 스냅샷 해시, 당시 제목 |
| 추가 trigger | 학교·확인 상태·항목 위치 검사, 목록과 항목의 UPDATE/DELETE 차단 |
| `school_service_migrations` | v7 적용 기록 1행 추가 |

명시적 마이그레이션 전에 기존 WAL 일관성 백업을 만든다. 기존 schema v1~v6에서 추가 적용할 수 있으며,
기존 행과 core `PRAGMA user_version`을 바꾸지 않는다. 실패한 DDL은 롤백하고 알 수 없는 버전은 중단한다.
Store 열기·웹 조회·저장·다운로드가 마이그레이션을 자동 적용하지 않는다.
v7이 없으면 설치 필요 안내만 표시하고 기존 임시 묶음 다운로드는 유지한다.

이번 검증은 외장 SSD의 격리 합성 SQLite에서만 적용했다. NAS 운영 DB에는 적용하지 않았다.
과거 버전 검사용 합성 fixture는 v7 테이블도 제거해 실제 이전 schema를 재현하도록 조정했다.
이 fixture 변경은 운영 DB 삭제/다운그레이드 명령으로 사용하지 않는다.
