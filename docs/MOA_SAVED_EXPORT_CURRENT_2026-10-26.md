# 저장한 묶음 상태·변경 확인과 최신 확인본 준비 — 19단계, 2026-10-26

## 담당자 흐름

1. 저장한 확인 완료본 묶음에서 **문서별 상태·변경 확인**을 연다.
   다운로드가 차단된 기존 화면에서도 같은 상태 화면으로 이동할 수 있다.
2. 저장 당시 확인 기록·HTML과 현재 제목·수신 번호·검수 번호/시각을 문서별로 대조한다.
   새 수신/정정본, 재변환, 확인 변경/미완료, 변환 중/실패, 근거/원본 목록 문제를 구분한다.
3. 모든 문서의 최신본이 확인을 마친 경우에만 확인란을 직접 선택하고
   **최신 확인본으로 새 묶음 준비**를 누른다.
4. 준비 결과의 포함 문서·확인 시점·경고를 다시 대조한다.
   이름을 입력하고 기존 목록 저장 기능으로 별도 목록을 저장한다.
5. 새 목록에서도 별도 확인란을 직접 선택한 뒤 ZIP을 받는다.
   재로그인 후 이전 목록과 새 목록을 각각 열 수 있다.

이전 저장 목록·원본·변환본·검수 이력은 덮어쓰거나 삭제하지 않는다.
상태 조회와 최신본 준비는 문서 검수·확인 완료 처리·변환 작업·공개를 실행하지 않는다.
미확인 문서를 제외하거나 과거 확인본으로 되돌려 부분 묶음을 만들지 않는다.
이전 목록의 버전이 달라졌으면 그 목록의 다운로드 차단도 계속 유지한다.

## HTTP·권한·동시 변경 계약

| 경로 | 동작 |
|---|---|
| `GET /confirmed-export/saved/status?id=…` | 소유자의 저장 목록을 최대 10건까지 현재 상태와 대조 |
| `POST /confirmed-export/saved/prepare-current` | 명시적 확인과 표시 당시 최신본 해시를 검증해 로그인 내 별도 준비 목록 생성 |

- 학교·담당자는 현재 인증 세션으로 결정한다. 소유자 외 다른 담당자·학교는 목록을 읽거나 준비할 수 없다.
- 최신본 준비에는 기존 쓰기 권한이 필요하다. 소유자가 reader로 변경되면 조회는 유지하고 준비는 차단한다.
  소속 해제·학교 비활성 상태는 기존 매 요청 인증 검사로 차단한다.
- 현재 수신본은 저장 항목과 **같은 학교·같은 게시글**의 `latest_version`에서만 찾는다.
  새 수신본의 변환/확인이 미완료이면 이전 확인본을 대신 사용하지 않는다.
- 목록의 모든 상태 대조와 준비는 하나의 SQLite 읽기 시점에서 수행한다.
  화면에 표시한 최신 수신/변환/확인 이벤트와 전체 스냅샷 해시를 POST에서 다시 계산·대조한다.
  표시 후 상태가 바뀌면 409와 새 대조 화면을 반환하고 준비 목록을 만들지 않는다.
- 버전이 같은 확인 이벤트의 근거 해시가 달라진 경우에도 단순히 새 해시를 채택하지 않고 차단한다.
- 준비 결과에는 당시 최신본의 고정 버전을 담는다. 준비 후 저장/다운로드 전 변경도 기존 검증으로 차단한다.
- 준비는 로그인당 최근 4개까지 유지된다. 영구 목록 저장과 ZIP 다운로드는 각각 별도의 명시적 조작이다.
  준비 화면에는 이전 저장 목록 연결을 표시한다. 저장 목록 사이의 새 계보 테이블은 만들지 않는다.
- 상태 화면은 버전과 원본 파일 목록·크기/경로를 대조한다. 원본 **파일 내용 SHA 검사는 ZIP 생성 시** 기존 코드로 다시 수행한다.
  같은 크기의 변조 파일도 ZIP 다운로드 단계에서 전체 차단된다.
- 기존 최대 10건, 원본 합계 64MiB, ZIP 내용 합계 96MiB 제한과 단건 원본 SHA/경로/크기 검사를 유지한다.
  일부 문서 ZIP이나 중간 ZIP을 디스크에 생성하지 않는다.
- GET query는 4,096자, 새 POST body는 16,384바이트로 제한한다.
  CSRF·Origin·중복/추가/빈 필드·잘못된 UTF-8·목록 ID·해시·확인 값을 검사한다.
  제목과 목록 이름은 HTML escape하며 기존 CSP·no-store를 유지한다.
- JavaScript가 꺼져 있어도 상태 조회·명시적 준비·저장·다운로드를 사용할 수 있다.
