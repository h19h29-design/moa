# MOA 저장 모델 평가 완료 — 2026-10-21

## 결론

결과 회수 문제를 수정하고 **재학습 없이 맥북 MPS에서 저장 모델의 별도 재로딩·평가를 완료**했다.
그러나 이진 후보의 정상 오탐이 더 나빠져 **성능 개선 실패**다. 운영에 적용하지 않는다.

## 같은 자료의 비교

이미 노출된 합성 개발 **54문항(정상18/오류36)**이다. 새 블라인드나 실제 학교 통신문 성적이 아니다.
각 문항의 실제 두 선택지 순서를 모두 사용하고, 두 순서의 확률을 평균해 판정한 결과다.
기존 모델 세 개는 해시로 고정한 과거 동일 입력·두 순서의 관측 기록이며 이번에 다시 추론하지 않았다.
이번에 새로 실행한 모델 평가는 저장된 이진 후보뿐이며 전부 맥북에서 수행했다.

| 모델 | 정답률 | 정상 오탐률 | 실제 오류 검출률 |
|---|---:|---:|---:|
| 기존 R1 | 48.1% (26/54) | 16.7% (3/18) | 30.6% (11/36) |
| 이전 대응 구간 후보 | 64.8% (35/54) | 94.4% (17/18) | 94.4% (34/36) |
| 이전 학습률 후보 | 66.7% (36/54) | 77.8% (14/18) | 88.9% (32/36) |
| 저장 이진 후보 | **64.8% (35/54)** | **100.0% (18/18)** | **97.2% (35/36)** |

- 이진 후보는 정상18건을 전부 오류로 판단하고 실제 오류1건을 놓쳤다. 미완료 입력은0건이다.
- 이전 학습률 후보보다 정확도1.9%p 감소, 정상 오탐22.2%p 증가다. 오류 검출만8.3%p 증가했다.
- 전부 오류라고 답해도66.7%인 자료 구성이다. 새 후보64.8%는 이 단순 기준보다도 낮다.
  균형 정확도48.6%, 내용 순위 AUC0.446으로 의미 판별 개선을 주장할 근거가 없다.
- 선택지 정방향만 사용하면 정확도57.4%/정상 오탐88.9%, 역방향은66.7%/100.0%였다.
  순서에 따라9/54문항의 답이 바뀌었고, 정상16건은 두 순서 모두 오판했다.
  **선택지 순서 영향뿐 아니라 오류 라벨 편중도 여전히 관측된다.** 원인별 추가 실험은 하지 않았다.
- 근거 부족 규칙으로 제외한 개발18건의 성공을 모델 정답에 합산하지 않았다.
  임계값을 이 시험에 맞춰 조정하거나 평가자료를 학습에 넣지 않았다.

## 회수 장애 원인과 수정

이전 경로는 평가 발행 전에856,349,269bytes(약817MiB)의 체크포인트 전체를 SSH로 회수했다.
180초 상한에서 시간 초과가 났으며, 모델 파일 전송이 맥북 내부 평가까지 막았다.
실제 네트워크 병목의 세부 원인까지 확정한 것은 아니다.

새 경로는 체크포인트를 맥북에 그대로 두고 파일별 SHA256을 스트리밍 계산한다.
원래 학습 계약·업데이트·누적 시간·자료/질문/라벨 매핑·모델과 optimizer 해시를 검증하고,
작은 JSON 영수증과 원판정만 미니로 회수한다. 모델을 메모리에 통째로 복사해 전송하지 않는다.
실제 사전 확인에서는 **6,520bytes를0.714초**에 회수하고7개 파일의 해시를 확인했다.
모델 해시 확인과 계약 확인은 별개로 수행했으며, 서버 값만 복사해 통과시키지 않았다.

기존에 봉인한 컨트롤러·맥북 평가기·학습 PLAN·허가·예산 원장은 수정하지 않았다.
사용자의 이번 명시 지시에 연결한 **평가 전용 복구 대장**을 분리했다.
이 경로에는 학습·예산 추가·운영 모델 교체 기능이 없다.
기존 중단 STATE는 이력으로 보존하고 복구 대장만 COMPLETE로 기록했다.
