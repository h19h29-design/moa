# 학교 담당자 전체 흐름 통합 검증 — 26단계, 2026-10-29

0~25단계의 학교 수신·검수·다운로드 기능을 연결해서 시험했다. 개발 환경의 전체 업무 흐름은
통과했으며, NAS 운영에는 적용하지 않았다. 이번 변경은 실제 발견한 CLI 상태 표시 오류 수정과
기존 형식별 통합 회귀 테스트 확장이다. 새 학교 수집기나 모델을 실행하지 않았다.

## 확인한 업무 흐름

| 구간 | 이번 확인 결과 |
|---|---|
| 직접 수신·변환 | 빈 합성 학교에서 HWPX·텍스트 PDF·별도 원본 첨부를 함께 업로드하고 역할을 확인한 뒤 실제 변환 워커 실행 |
| 구조·수정 | 파일 3개·구역 10개·관계 7개를 조회하고 본문 금액 수정. HWPX 헤더/각주 관계와 PDF의 분석 한계 경고 유지 |
| 임시저장·복구 | 입력 후 자동 임시저장 완료 표시 확인. 로그아웃하고 새 브라우저 프로필로 로그인해 텍스트·사유 복구 |
| 정식 검수·확인 | 개인 입력을 명시적으로 정식 수정본에 반영하고 고정 HTML을 대조한 뒤 확인 완료. 미확정 범위·경고는 유지 |
| 저장 묶음 | 확인한 버전의 목록을 저장하고 실제 ZIP 다운로드. 원본 3개와 HTML·목차 manifest 해시 검증 |
| 영수증·검색 조건 | 내려받은 ZIP의 크기·SHA-256이 영수증과 일치. 조건을 저장하고 새 로그인·모바일에서 같은 전체 CSV 다운로드 |
| 변경·권한 보호 | 확인 취소 후 기존 묶음은 409로 차단. 이전 검수 HTML·원본 ZIP·영수증은 보존. 학교 B에서 학교 A 목록·문서 접근 404 |
| 합성 백업 복원 | 일관 DB 백업과 합성 객체를 같은 SSD의 별도 경로에 복원. 읽기 전용 서버에서 이전 HTML·원본 ZIP·저장 조건 CSV 재조회 |

확인 완료는 담당자 검수 상태이며, 자동 분석의 완전성이나 공개 승인으로 바꾸지 않는다.
영수증은 ZIP 전송 직전의 기록이며 수신 완료 보증이 아니다. CSV 다운로드는 새 영수증을 만들지 않는다.

## 수정과 회귀 보호

`moa.school_cli migrate`가 학교 스키마 v10 설치 후에도 `school_schema=2`를 출력했다.
이제 성공한 마이그레이션의 실제 설치 버전을 DB에서 읽어 표시한다. 마이그레이션 DDL·권한·백업 방식은
변경하지 않았다. 신규 설치, 반복 실행의 v10 표시와 추가 백업/행 변경 없음, 알 수 없는 미래 버전의
거절 및 성공 메시지 없음까지 CLI 테스트로 확인했다.

기존 `test_school_formats.py`의 실제 파서→HTTP 검수→재로그인 묶음 다운로드 시나리오를
영수증 검색·조건 저장·재로그인·CSV까지 연장했다. 실제 ZIP 크기/해시 일치, 다른 학교 접근 거절,
정식 검수 재개 뒤 전체 다운로드 차단, 이전 HTML/ZIP과 원본 hash/mtime·영수증 보존을 함께 검증한다.
