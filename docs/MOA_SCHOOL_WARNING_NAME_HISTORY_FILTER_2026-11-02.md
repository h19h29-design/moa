# 저장한 분석 경고 조건 이름 이력 검색·기간 필터 — 33단계, 2026-11-02

32단계의 이름 복원에 **이름 키워드·기간으로 이력만 골라 보는 검색**을 추가했다.
이력은 추가형으로만 남고, 검색은 읽기 전용이다. 저장 조건·문서·변환본·보관 상태·원본·검수 이력·영수증은 그대로다.

## 담당자 사용 흐름

1. **저장한 경고 검색 조건 → 이름 변경과 이력**을 연다.
2. **이름 이력 검색**에서 이름 일부와 시작일·종료일을 넣고 **이력 검색**을 누른다.
   이름은 앞뒤 공백을 제거하고 NFC로 정규화한 뒤 대소문자·유니코드 형태를 구분하지 않고 부분 일치로 찾는다.
   기간은 그 날짜를 포함한다. 두 조건을 함께 쓰면 둘 다 맞는 기록만 나온다.
3. 결과는 **이름 기록 N개 · 전체 M개**로 표시하고, 조건에 맞는 기록이 없으면 안내와 **이력 검색 지우기**를 보여준다.
4. 페이지를 넘겨도 입력한 이름·기간과 목록 검색어·상태·목록 페이지가 유지된다.
   복원 확인·취소·이름 변경 뒤에도 같은 필터로 돌아온다.
5. 필터는 이 화면의 이력에만 적용한다. 목록의 이름 검색, 현재 이름, 보관 상태는 바뀌지 않는다.
6. 재로그인 후에도 이력과 저장 조건이 남는다. JavaScript 없이 기본 HTML 폼·링크로 동작한다.

## DB·권한·입력·보존 계약

- 새 테이블·스키마 마이그레이션이 없다. 기존 학교 스키마 **v13**의 `school_warning_search_names`를 그대로 읽는다.
  v13 미설치 화면은 기존처럼 명시적 마이그레이션 안내만 보여주고 검색 폼·이름 폼을 표시하지 않는다.
  HTTP는 자동 마이그레이션하지 않는다.
- 조회는 `_snapshot` 읽기 범위에서 조건 ID·학교·계정으로 좁힌 **이름 이력 행만** 읽는다.
  원본·추출 캐시·분석 JSON·검수·초안·묶음·영수증을 읽거나 모델을 호출하지 않는다.
- 이름 필터는 연결 로컬 스칼라 함수 `moa_warning_name_key`(NFC+casefold)와 `instr`로 비교한다.
  `%`·`_`는 와일드카드가 아니라 글자 그대로 취급하고, SQL 문자열을 만들지 않는다.
- 기간은 `YYYY-MM-DD`만 받는다. 존재하지 않는 날짜(`2026-02-30`), 자리수가 다른 값, 시작일이 종료일보다 늦은 값은 400이다.
  이름은 최대 120자이며 빈 값은 "조건 없음"이다. 제어 문자·잘못된 UTF-8·잘못된 숫자 페이지는 400이다.
- GET `/structure-warning-searches/name`의 허용 쿼리는 `id/page/q/state/list_page/hq/hf/ht` 하나씩이다.
  중복·미지 파라미터, 4KiB 초과 쿼리는 400이다.
- 이름 변경·복원 POST는 기존 CSRF·Origin·4KiB·엄격한 필드 검사에 `hq/hf/ht`를 더한다.
  값은 다시 검증하며 폼 밖 이름·학교·계정·기간 주입은 거절한다. 성공 시 같은 필터의 이력으로 돌아간다.
- 다른 학교와 같은 학교의 다른 계정은 필터 화면·복원 확인에 접근할 수 없다(404).
  본인의 읽기 역할은 조회만 가능하고 제출은 403이며, 소속 해제 시 조회도 차단한다.
- 이름·시각은 HTML 이스케이프하고 기존 `private, no-store` 응답을 유지한다.
- 저장 조건 행·이름 이력·보관 이벤트·수신본·변환 버전·검색 필터·원본·검수·초안·묶음·영수증을 수정하지 않는다.
  기존 HTML·ZIP·CSV와 버전 변경 시 다운로드를 차단하는 계약도 그대로다.
