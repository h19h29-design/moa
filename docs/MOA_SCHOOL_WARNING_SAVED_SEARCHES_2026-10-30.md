# 분석 경고 검색 조건 저장·다시 불러오기 — 29단계, 2026-10-30

28단계의 문서별 경고 검색에 **내 검색 조건 저장 목록**을 추가했다.
학교·계정별로 이름을 붙여 저장하고 재로그인 후 같은 문서·변환 버전에서 다시 검색한다.

## 담당자 사용 흐름

1. 통신문의 **분석 경고 모아보기**에서 파일·경고 유형·검색어를 적용한다.
2. 검색 조건 이름을 입력하고 **현재 경고 검색 조건 저장**을 누른다.
   저장되는 값은 검색 버튼으로 적용한 조건이며, 입력 중인 미적용 조건은 먼저 검색한다.
3. 상단 **저장한 경고 검색 조건**에서 내 목록을 확인한다. 이름·문서 제목·조건·저장 시각·변환 버전을 표시한다.
4. **경고 검색 조건 불러오기**로 저장 당시 변환본의 첫 검색 페이지를 연다.
   마지막 페이지에서 저장해도 페이지 위치는 저장하지 않는다. 조건 목록과 경고 결과는 각각 20건씩 표시한다.
5. 로그아웃·재로그인, 서버의 DB 재개방 뒤에도 유지된다. 새 변환이 생겨도 최신본으로 자동 변경하지 않는다.

저장한 이름·조건은 덮어쓰지 않는다. 다른 조건은 새 항목으로 저장한다.
경고 검색 결과 자체나 경고 해결 상태·검수 승인을 저장하는 기능은 아니다.
결과가 없거나 처음부터 경고가 없는 문서도 조건을 저장할 수 있으며, 원본 대조가 필요하다는 안내를 유지한다.

## DB·권한·보존 계약

- 학교 스키마 **v11**: `school_warning_searches` 테이블·소유자 조회 인덱스·범위/불변 트리거만 추가한다.
  수신본·변환본·학교 소속을 FK와 삽입 트리거로 연결한다. 기존 테이블의 행이나 core `user_version`은 변경하지 않는다.
- 저장 열: 임의 항목 ID, 학교·계정, 이름, 수신본·변환본 ID, 문서 제목,
  정규화된 검색어·파일/유형 필터, 저장 당시 파일/유형 표시 문구, 저장 시각이다.
  페이지 위치·문서 본문·검색 결과 목록을 복제하지 않는다.
- 기존 명시적 `school_cli migrate` 경로가 전체 DB의 일관 백업을 만든 뒤 트랜잭션으로 추가한다.
  재호출은 중복 백업·DDL 없이 종료하며 실패하면 롤백한다. 이번 적용은 외장 SSD 합성 DB에 한정한다.
  HTTP 요청과 기존 수집기는 자동 마이그레이션하지 않는다. 미설치 시 기존 경고 검색은 유지하고 저장 기능의 필요 상태를 안내한다.
- `POST /structure-warning-searches/save`는 현재 로그인·CSRF·Origin·쓰기 역할을 확인한다.
  허용된 필드 하나씩만 받고 학교/계정 위조 필드, 중복 필드, URL 쿼리, 알 수 없는 필터를 거절한다.
  이름/검색어 120자, 파일/유형 필터 512자, 폼 8KiB, 재사용 URL 4KiB 한도를 둔다.
- 같은 항목 ID와 같은 정규화 조건의 재전송은 한 행을 재사용한다. 다른 유효 내용은 409 충돌로 처리한다.
  저장 테이블은 UPDATE/DELETE 트리거로 기존 항목의 변경을 차단한다.
- `GET /structure-warning-searches`와 `/structure-warning-searches/open?id=…`는 현재 소속을 다시 확인한다.
  다른 학교와 같은 학교의 다른 계정 항목은 목록에 없으며 직접 ID로 접근해도 404다.
  쓰기 권한이 사라진 담당자는 기존 자기 항목을 조회할 수 있지만 새 저장은 할 수 없다. 소속 해제 시 조회도 차단한다.
- 목록은 저장 메타데이터만 읽는다. 불러오기는 해당 수신본의 실제 고정 분석과 필터를 검증한 뒤 기존 경고 검색으로 연결한다.
  임의 외부 URL이나 최신 변환으로 대체하지 않는다. 필터·이름·문서 제목은 HTML 이스케이프하고 기존 `private, no-store` 응답을 유지한다.
- 원본·추출 캐시·분석 JSON·검수 이력·개인 입력·확인 목록·다운로드 영수증은 수정하지 않는다.
  기존 HTML/ZIP/CSV 생성 경로와 바이트를 유지한다. 문서 버전 변경 시 기존 묶음 다운로드를 차단하는 계약도 유지한다.
