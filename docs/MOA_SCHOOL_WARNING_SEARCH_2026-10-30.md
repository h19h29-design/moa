# 문서별 분석 경고 모아보기·검색 — 28단계, 2026-10-30

여러 첨부의 분석 경고를 한 화면에서 찾는 읽기 전용 기능을 추가했다.
27단계의 쉬운 설명·확인 방법·파일 위치를 재사용하며, 원래 분석이나 담당자 확인 결과를 변경하지 않는다.

## 사용 흐름

1. 자동 분석·담당자 검수·최종 확인·변경점 비교·저장본 미리보기에서
   **이 변환본의 분석 경고 모아보기·검색**을 연다.
2. 파일, 경고 유형, 검색어를 함께 적용한다. 같은 이름의 첨부도 파일 번호로 구분한다.
3. 검색된 경고의 설명·확인할 내용·원래 근거를 보고 같은 변환본의 해당 파일 또는 자동 분석 구역으로 이동한다.
4. 경고는 20건씩 표시한다. 검색은 모든 페이지의 항목을 대상으로 하며 페이지 이동 시 조건과 버전을 유지한다.
5. 검색 초기화는 같은 변환본의 전체 경고로 돌아간다. 조회 URL을 보관하면 재로그인 후에도 같은 버전·조건으로 열 수 있다.
   서버에 검색 조건이나 새 검수 목록을 저장하는 기능은 아니다.

검색 대상은 제목, 설명, 확인할 내용, 파일 위치, 본문에서 언급된 첨부 이름과 경고 코드다.
검색어는 최대 120자이며 Unicode 조합형 차이와 대소문자를 정규화한다.
`%`·`_` 등의 문자는 와일드카드나 정규식으로 해석하지 않는다.
파일과 경고 유형은 교집합으로 적용하며, 각 선택 항목 옆 건수는 검색 전 전체 변환본 기준이다.
**전체 경고 수·검색 결과 수·현재 페이지 범위**를 구분해서 표시한다.

문서 묶음 경고나 파일 위치를 특정할 수 없는 경고도 별도 파일 필터로 찾는다.
등록되지 않은 새 경고 코드도 누락시키지 않고 일반 안내와 원래 코드를 보존한다.
중복 관찰을 합치거나 분석 순서를 바꾸지 않는다.
검색 결과가 없을 때는 원래 경고가 그대로 남아 있음을 안내한다.
처음부터 경고가 없는 변환본도 원본 대조가 필요하다고 표시하며 확인 완료로 간주하지 않는다.

## 데이터·권한 계약

- 새 GET 경로: `/structure-warnings?id=수신본&revision=변환본`.
  두 식별자가 모두 필요하다. 누락·공백, 알 수 없는 필터, 중복 쿼리, 잘못된 페이지와 범위 초과는 400이다.
- 학교 소속 검사와 기존 `structure_for`를 거쳐 그 수신본에 속한 변환본만 읽는다.
  다른 학교나 다른 수신본의 변환 ID를 섞으면 404, 미로그인·소속 해제 이후에는 401이다.
  같은 학교의 읽기 담당자도 조회할 수 있다.
- 최신 변환으로 자동 전환하지 않는다. 재변환 이후에도 과거 URL의 경고·전체 보기·위치·페이지 링크는 원래 변환본을 가리킨다.
- 파일 필터의 출처 판정은 27단계 위치 안내와 같다. 구역 ID만 있으면 같은 변환본에서 파일을 찾고,
  서로 다른 파일의 구역이 섞이면 해당 구역으로 잘못 연결하지 않는다.
- 파일명·검색어·코드·참조는 HTML 이스케이프하며, 외부 참조를 요청하거나 실행하지 않는다.
  응답은 기존 인증·`no-store`·보안 헤더를 유지한다. 새 JavaScript나 외부 라이브러리·네트워크 요청은 없다.
- DB 테이블·스키마 버전·마이그레이션·작업 큐·분석기는 변경하지 않는다.
  원본 객체·추출 캐시, 자동 분석 JSON, 검수 이벤트·초안, 확인 완료 목록, 다운로드 영수증 행을 수정하지 않는다.
- 기존 저장 HTML·ZIP·영수증 CSV 생성 경로와 바이트를 보존한다.
  쉬운 안내·검색 화면은 인증된 웹 화면이며 기존 다운로드 파일의 내용을 재작성하지 않는다.

## 실제 검증

- 신규 검색 검사와 기존 경고 안내 검사 **63개 통과**. 실제 HTML·HWPX·텍스트 PDF·텍스트 첨부를 기존 파서로 처리했다.
  동일 파일명, 첨부 누락, 각주 연결, 알 수 없는 코드·위치, Unicode·문자 그대로의 검색,
  필터 교집합, 45건의 전체 검색·3페이지 이동, 빈 결과, 권한·입력 차단을 포함한다.
- 최종 전체 회귀: **2,307 passed / 17 skipped / 실패 0, 569.03초**. 기존 선택적 의존성·맥북 전용 검사·비공개 HWP fixture 제외를 유지했다. 학습·모델 추론으로 대체하지 않았다.
- 기존 Playwright·Chrome으로 **브라우저 13개 항목 통과**, 콘솔 오류·경고 0.
  1280×900 데스크톱과 390×844 모바일에서 직접 폼 조작·필터·페이지·근거 펼치기·위치 이동을 시험했다.
  두 화면 크기에서 가로 넘침이 없으며, 스크린샷을 직접 확인했다.
  재로그인 후 URL 재사용, JavaScript 비활성 동작, 학교 B 차단, 기존 HTML 실제 다운로드도 통과했다.
- 같은 합성 DB를 `PRAGMA query_only=ON`으로 열어 브라우저 시험했다.
  모든 DB 행, 원본·추출 캐시의 SHA/mtime, 분석 JSON, 저장 HTML·묶음 ZIP·영수증 CSV가 조회 전후 동일했다.
  종료 후 `quick_check=ok`, 외래 키 오류 0이다.
- 브라우저 검사에서 선택 항목 문구가 드롭다운 이름에 섞이는 것을 확인해 명시적인 접근성 이름을 추가했다.
  첫 HTTP 시험의 폼 선택도 검색 폼으로 범위를 좁혔다. 최종 코드로 브라우저와 전체 회귀를 다시 실행해 통과했다.
- `compileall moa tests`, `sh -n scripts/install-nas.sh`, `git diff --check` 통과. 최종 변경 파일 8개의 비밀 패턴 검사 발견 사항 0건이다.

Browser 플러그인이 없어(`Browser plugin not available`) 기존 설치된 Playwright와 Chrome을 사용했다.
패키지·브라우저를 설치하거나 다운로드하지 않았다. 브라우저 요청은 합성 시험 서버의 loopback으로 제한했다.
이는 실학교 담당자의 수용 시험이나 NAS 운영 배포 검증을 대신하지 않는다.
